Use cases

How is Google Maps Lead Enrichment Scraper different from Contact Page Audit & Business Channel Extractor and Bulk URL Status Checker?

This Actor enriches existing Google Maps exports, place lists, or local business lead rows you already have. It does not scrape Google Maps itself. Live inputs are leads (existing Google Maps/local business lead objects) and optional sourceDatasetId (an Apify dataset of lead rows to read). Contact Page Audit & Business Channel Extractor inventories public business contact channels from contact, about, support, policy, and company pages you supply. Required input is urls (maximum 100). Person-level email candidates are suppressed. Bulk URL Status Checker checks a known URL list for HTTP status, redirect chains, response timing, and broken URL findings. Required input is urls (maximum 1000). It does not crawl pages. Use this Actor to append website, contact, social, health, and business-signal fields to lead rows. Use Contact Page Audit when the job is a contact-page channel inventory. Use Bulk URL Status Checker when the job is HTTP status on URLs you already have.

What input is required?

The live OpenAPI input schema has no required array. The README says use leads for direct rows or sourceDatasetId to read an existing Apify dataset. Live fields are leads (array; Existing Google Maps/local business leads; each item can include businessName/name/title, address, website/url/domain, phone, email, placeUrl, and sourceUrl; default/prefill is Example Cafe at 1 Market St, San Francisco, CA), sourceDatasetId (string, default empty; Optional Apify dataset ID containing lead rows to enrich. The actor reads this dataset; it does not scrape Google Maps.), includeContacts (boolean, default true; Fetch public website/contact pages to find public emails, phones, and social profile links.), includeWebsiteContent (boolean, default true; Capture lightweight website title, meta description, and business signal keywords.), includeHealth (boolean, default true; Record HTTP status and response time for the public website.), maxLeads (integer, default 50, minimum 1, maximum 1000; Maximum lead rows to enrich.), delivery (string enum dataset or dataset_and_webhook, default dataset), webhookUrl (string, default empty; Optional HTTPS endpoint when delivery is dataset_and_webhook.), and dryRun (boolean, default false; Validate input and produce preview rows without fetching websites, pushing dataset rows, charging PPE events, or sending webhooks.).

What does a result row contain?

The published README What it returns list is business name, address, website, normalized domain; public emails, phones, contact page, and social links; lightweight website signals and optional HTTP health status; and status, chargedEvent, sourceUrls, and errors for billing auditability. The Store description also names confidence, PPE charged events, and no-charge invalid rows. There is no published output JSON schema sample object on the Store README. That field list is the published README inventory, not a live coverage guarantee for every input row.

README charged-event keys for useful rows are lead_profile_enriched and lead_partial. Downstream classification also names invalid, not found, and errored rows. This is not a full-page markdown extract and not a contact-page public_contact_channel inventory — those jobs belong on Website Content Extractor and Contact Page Audit & Business Channel Extractor.

Does it scrape Google Maps or search for local businesses?

No. The live Store description states this actor does not scrape Google Maps itself. The README states it does not scrape Google Maps itself and works on user-provided rows or an Apify dataset you already have. The live sourceDatasetId description repeats: The actor reads this dataset; it does not scrape Google Maps. It does not run Maps search, place discovery, or Maps listing scrape. Supply existing Google Maps exports, place lists, or local business lead rows.

Public emails, phones, and social profile links come from public website/contact pages when includeContacts is true. Lightweight title, meta description, and business-signal keywords come from includeWebsiteContent. HTTP status and response time for the public website come from includeHealth. All three flags default to true.

How do dataset delivery, webhooks, and dry runs work?

delivery defaults to dataset (write enriched leads only to the dataset). Set delivery to dataset_and_webhook and provide webhookUrl (HTTPS) to also send the final rows after the run. dryRun true validates input and produces preview rows without fetching websites, pushing dataset rows, charging PPE events, or sending webhooks. Live schema delivery values are dataset and dataset_and_webhook; webhook alone is not a live enum value.
