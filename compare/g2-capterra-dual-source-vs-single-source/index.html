When dual-source is the better lane

Mix G2 and Capterra in one run after the one-URL schema check. Dual-source support accepts both g2.com/products/*/reviews and capterra.com/p/*/reviews/ URLs. The Actor classifies each URL and routes it to the matching parser. Factual benefits versus two separate single-source scrapers:

  • One Actor — one input schema, one dataset export
  • Aligned fields — ratings, rating breakdowns, nested pros / cons
  • Less glue code — no join across two unrelated row shapes
{
  "reviewPageUrls": [
    "https://www.g2.com/products/notion/reviews",
    "https://www.capterra.com/p/147384/Notion/reviews/"
  ],
  "reviewLimit": 1,
  "delivery": "dataset",
  "dryRun": false
}

Keep reviewLimit at 1 until the dual-source row shape is useful. Use dryRun: true for validation-only checks before larger monitoring runs. Total cost mainly follows how many reviewPageUrls you process and how deep you sample reviews. There is no separate published per-review billing event.

What does not change between the two

  • Billing is pay-per-event: Actor Start plus one result event per default-dataset item.
  • Live schema fields are reviewPageUrls, reviewLimit, delivery, webhookUrl, and dryRun. Do not send unpublished README aliases such as products, source, slug, maxReviewsPerProduct, or emitDeltas.
  • Reviews are extracted from server-rendered HTML. Pages that render reviews only via client-side JavaScript may return partial results. Blocked requests are reported honestly.

What is a dual-source G2 + Capterra review scrape?

Dual-source means one run of G2 & Capterra Review Scraper with both G2 and Capterra review-page URLs in reviewPageUrls. The Actor auto-detects source and routes each URL to the matching parser. When is a single-source G2 or Capterra run enough?

Use a single-source run when you only have review pages from one catalog, or when you are still validating the schema. The live Store Quickstart is one G2 URL with reviewLimit 1. Can one run mix G2 and Capterra reviewPageUrls?

Yes, after a one-URL schema check. Dual-source support accepts both G2 (g2.com/products/*/reviews) and Capterra (capterra.com/p/*/reviews/) URLs in reviewPageUrls. The Actor classifies each URL and routes it to the matching parser. Use dryRun true for validation-only checks before larger monitoring runs.

What fields stay aligned across G2 and Capterra?

Each product row can include source (g2 or capterra), productName, overallRating, totalReviewCount, ratingBreakdown, and nested reviews[] with title, rating, date, author, body, pros, cons, and verified. status is ok, partial, blocked, or error. That shared shape is the glue-code saving versus merging two unrelated scrapers.

How is a billed result different from one nested reviews[] item?

The live billed event title is result at $0.003 for a single result in the default dataset. The published README output is a per-product object with nested reviews[]. There is no separate published per-review billing event. Total cost mainly follows how many reviewPageUrls you process and how deep you sample reviews.

Do I need two Actors to scrape G2 and Capterra?

No. One Actor accepts both catalogs in reviewPageUrls. Single-source is a smaller input on that same Actor, not a different product. Dual-source is the same Actor with mixed URLs after the one-URL schema check.

Does this Actor accept Shopify slugs or Apple podcast review IDs?

No. Required input is reviewPageUrls. additionalProperties is false. Shopify App Store merchant listings belong on Shopify App Store Review Scraper. Apple/iTunes podcast review RSS belongs on Apple Podcasts Reviews Scraper.
