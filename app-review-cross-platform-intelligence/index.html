How is iOS & Android App Review Scraper different from Chrome Web Store Extension Intelligence and G2 & Capterra Review Scraper?

iOS & Android App Review Scraper (taroyamada/app-review-cross-platform-intelligence): This Actor pulls public App Store and Google Play review samples for one product, clusters complaint themes, and writes one buyer-ready summary row per monitored app. Google Play usually exposes about 20 public cards without deeper pagination. Not a full review-export crawler, not G2/Capterra, and not review generation. Live PPE is one summary row, not per-review billing. Chrome Web Store Extension Intelligence is for Chrome extensions (input extensionUrls; Chrome Web Store; extension metadata). Not iOS/Android reviews. G2 & Capterra Review Scraper is for B2B SaaS reviews (input reviewPageUrls; G2/Capterra; review rows). Not mobile storefront samples. Website Content Extractor is for Page markdown (input urls; HTML; markdown). Not store reviews.

What input is required?

Live required fields: none listed (see live fields). exampleRunInput is Duolingo appleApp 570060128 + googlePlayApp com.duolingo, reviewLimitPerPlatform 20. No schema required array; supply at least one store object. Play pagination is intentionally shallow.

Field Type Default Notes
productName string empty Product Name. Optional label for the monitored product. If empty, the actor uses the best store title it finds.
country string us Default Country Code. Default ISO country code for both stores. App Store lookups and review feeds use lowercase values like us, gb, jp.
language string en_US Google Play Language. Google Play language code for the public page request, for example en_US.
appleApp object empty App Store App. Optional App Store target. Provide {"appId":"570060128"} or {"url":"https://apps.apple.com/us/app/id570060128"}.
googlePlayApp object empty Google Play App. Optional Google Play target. Provide {"appId":"com.duolingo"} or a full play.google.com URL.
reviewLimitPerPlatform integer 20 Review Sample Limit Per Platform. Maximum reviews to analyze per platform. Google Play usually exposes about 20 public review cards without deeper pagination; App Store can return more from RSS pages.
lookbackDays integer 180 Lookback Window (Days). Prefer reviews inside this window. If a source has no matches inside the window, the actor falls back to the public sample and flags the fallback in warnings.
minThemeMentions integer 2 Minimum Theme Mentions. Minimum complaint mentions before a theme is treated as a real cluster instead of one-off noise.
delivery string dataset Delivery Mode. Dataset is the default. Webhook still writes the local output file and dataset row, then posts the summary payload to the webhook URL.
webhookUrl string empty Webhook URL. Webhook URL to receive the summary payload when delivery is webhook.
snapshotKey string empty Snapshot Key. Optional override for the monitoring snapshot key. Leave empty to derive it from the configured app IDs and locale.
nowIso string empty Debug Timestamp Override. Optional ISO timestamp override for deterministic tests or backfills.
dryRun boolean false Dry Run. If true, the actor skips dataset delivery, webhook delivery, and snapshot writes. Local output is still written.

How do dataset, webhook, and dry-run delivery work?

delivery defaults to dataset on the live schema. Dataset output is the billable surface when rows are written. webhookUrl is used when delivery is webhook (and typically not during dryRun). dryRun true validates or samples without the usual dataset/webhook side effects described on the Store schema. Unchanged runs that write zero default-dataset rows typically charge $0.00 on current PPE.
