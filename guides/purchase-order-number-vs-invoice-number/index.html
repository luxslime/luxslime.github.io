Purchase order vs invoice number

Purchase-order number vs invoice number: two different references

Direct answer. A purchase-order number is the buyer’s reference on the document that authorizes a purchase. An invoice number is the seller’s reference on the document that asks for payment. They are issued by different parties, at different moments, and they are not interchangeable: a string that matches a PO format is not proof of an invoice, and an invoice number is not a purchase-order number. Who issues which number

Purchase-order number vs invoice number
Purchase-order number Invoice number
Issued by The buyer (their purchasing system) The seller (their billing system)
What it identifies The buyer’s authorization to buy The seller’s request for payment
Typical moment Before or at order, so the seller can put it on the order When the seller bills, often after fulfilment
Shopify B2B checkout field The PO number field on a company checkout Not that field

Buyers set their own PO formats. There is no universal pattern. Example shapes and regexes live on purchase-order number format examples. An invoice series is a different numbering scheme; do not paste invoice samples into a PO format rule and treat a match as a valid purchase order.

What a checkout PO rule can and cannot do

A Cart and Checkout Validation function can read cart.poNumber and reject a company checkout when the field is empty or fails the pattern you publish. That is a PO-number rule. It does not issue invoices, does not match the string to a buyer’s purchasing system, and does not prove the order was approved or paid.
