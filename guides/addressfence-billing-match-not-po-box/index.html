Billing match is not a PO Box block

Requiring shipping and billing to match does not detect PO Boxes — it only forces the two addresses to be identical

AddressFence (Shopify App Store) is a Shopify checkout-validation app for billing-address rules and street-number checks — the address rules built-in validation cannot apply. Built-in checkout rules cannot target billing at all. Test any address in the simulator before publishing, with one-click rollback.

Shopify’s “require shipping and billing address to match” preference is a fraud-control option. It makes the two addresses the same. It does not inspect either address for a PO Box. If the matched address is a PO Box, both sides remain a PO Box.

Native match preference: identical addresses, not a PO Box detector

Shopify Help: address collection preferences documents the control at Settings → Checkout → Address collection: Require shipping and billing address to match. The job is identical addresses. Help recommends it for stores with a high amount of fraudulent orders, paired with an Address Verification System. A side effect is that customers cannot send gifts to a different shipping address.

That preference does not read address lines for “PO Box”. Copying shipping into billing, or forcing the two fields to be the same, still leaves a PO Box on both sides when the shared address is a PO Box.

Native shipping format rules do not become a billing PO Box check

Shopify Help: address format validation in Checkout Blocks can block PO Box addresses on the shipping address. Help states that only shipping addresses are validated, and that billing address fields are not supported and cannot be targeted by those rules.

Requiring billing to match shipping does not add a billing PO Box detector. The format rule still watches shipping. The match preference still only asks whether the two addresses are identical. A buyer who bills and ships the same PO Box still checks out with a PO Box on the card billing address.

Billing-targeted validation for a PO Box or missing street number

To reject a PO Box — or a missing street number — on the card billing address, publish checkout validation that reads billing. AddressFence lists that job as billing-address rules: built-in checkout rules cannot target billing at all. The same listing covers “Require a street number - the Address Blocker rule that was not migrated.” Test any address in the simulator before publishing, with one-click rollback.

Not the same as AVS, risk scores, carriers, or a purchase-order number

  • Not AVS or card-issuer address checks. Help pairs the match preference with an Address Verification System; matching shipping to billing is not that issuer check.
  • Not a change to Shopify’s order-risk score. Identical addresses are a checkout collection preference, not a risk-score rule.
  • Not carrier delivery restrictions. Hiding rates for a ship-to does not inspect the card billing address.
  • Not B2B purchase-order number rules. A PO number on an invoice is a different job: require a PO number at B2B checkout.
  • Not postal vs purchase-order confusion. Blocking a postal PO Box on billing is not the same as requiring a buyer’s PO number.

App path: billing-address rules and require a street number

  1. Open the AddressFence listing (apps.shopify.com/address-guard) and install it.
  2. Enable billing-address rules and require a street number as the listing describes: built-in checkout rules cannot target billing at all, and require a street number (the Address Blocker rule that was not migrated). Test any address in the simulator before publishing, with one-click rollback.
  3. Publish to checkout validation.
