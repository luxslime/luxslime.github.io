PO box blocker for the billing address, not just shipping

AddressFence (Shopify App Store) is a Shopify checkout-validation app for billing-address rules — built-in checkout rules cannot target billing at all — and for require a street number, the Address Blocker rule that was not migrated. Require a street number after the Address Blocker sunset

Full street-number guide →

After Checkout Blocks Address Blocker sunset on 31 August 2026, native Shopify does not support “require a street number”; AddressFence adds that check back as checkout validation — the Address Blocker rule that was not migrated.

On 17 June 2026, Shopify made address format validation available to all merchants at Settings → Checkout → Checkout rules → Address format validation. Compatible Address Blocker settings moved automatically, but the street-number rule did not. Shopify’s Help Center says: “Requiring a street number isn't supported in address format validation. You can require additional address fields in your checkout settings instead.”

Additional address fields are not a general replacement. Those extra fields (Street name + Building number) appear only for Brazil, Kuwait, Panama, Peru, and the Philippines, plus an early-access list (Belgium, Chile, Colombia, Costa Rica, Germany, Indonesia, Israel, Mexico, Netherlands, Saudi Arabia, Spain, Taiwan, Turkey, UAE, Vietnam). Merchants cannot change which fields appear or which are required. Some accelerated checkouts such as PayPal do not require them. The fields are unavailable if address labels were renamed or an app reads or edits address data (Checkout Blocks excepted).

If you sell into the United States, the United Kingdom, Canada, Australia, or anywhere else outside that list and relied on “require street number”, that check is gone from native checkout. Billing address fields also cannot be targeted. AddressFence adds the street-number rule back: a street line with no house number is rejected at checkout. The same listing also covers billing-address rules for PO boxes.

Post-sunset checklist:

  1. Open Checkout rules and confirm the migrated address format validation rules exist.
  2. Test a PO Box on shipping.
  3. Test a street line with no number.
  4. Test a PO Box on billing.

Street number is a sibling rule

See Require a street number after the Address Blocker sunset.

Blocking a PO Box answers “is this a PO Box?” Requiring a street number answers a different question: “does this street line include a house number?”

Shopify’s older Address Blocker / require street number app sunset on 31 August 2026 and was not migrated into Checkout Blocks address-format validation. Merchants who still need “no bare street line without a number” need a separate check.

Treat street-number as a sibling of the billing PO Box job on this same page:

Does a shipping PO Box block also stop PO Box billing?

No. Native address format validation in Checkout Blocks can block PO Boxes and similar types on the shipping address. The Help Center states that billing address fields are not validated by that rule. A buyer can ship to a street address and still put a PO Box on the card billing address unless something else rejects billing.

Can I just require shipping and billing to match?

That native preference forces the two addresses to be the same. It is a fraud-control option, not a PO Box detector. It also blocks legitimate gift checkouts where shipping and billing should differ. If the matched address is a PO Box, both sides stay a PO Box. Use a billing-targeted checkout validation rule when the job is “no PO Box on billing.” Dedicated walkthrough: requiring billing to match shipping is not a PO Box block.

Do carrier restrictions or delivery profiles cover billing?

No. Hiding rates for PO Box shipping (carrier rules, delivery customizations) only affects how the order ships. Digital carts and “billing different from shipping” still collect a billing address. Native shipping tools do not publish a first-class “block PO Box on billing” toggle.

How do I block PO Box on billing at checkout?

Publish a checkout validation function that reads the billing address (not only shipping) and returns a field error on PO Box patterns. AddressFence (listing handle address-guard) is the App Store app this site already uses for billing-address rules — built-in checkout rules cannot target billing at all — and for the street-number rule Address Blocker did not migrate. Open the listing, configure those rules, and publish to checkout validation.

Will this also block military, diplomatic, or parcel-locker addresses?

Native shipping address-format rules can include diplomatic, military, parcel locker, PO Box, and USPS gopost® — still on shipping, not billing. Do not copy every shipping block onto billing unless that is the actual policy. AddressFence listing jobs are billing-address rules and require a street number.

Does blocking a PO Box on billing stop fraud?

No. It only rejects addresses that match the patterns you publish. It is not an AVS replacement, not a chargeback guarantee, and not legal advice. Pair it with the payment protections you already use. False positives happen if a street address contains “PO Box” in a second line.

What if the cart has no shipping address?

Digital or shipping-not-required carts still have a billing address. A shipping-only PO Box rule never runs on those checkouts. That is the case where a billing-targeted rule matters most. Confirm billing-address rules are published.
