Block PO Box on the billing address, not just shipping

Job: reject a PO Box on the card billing address at checkout. Blocking a PO Box on shipping is a different control.

Native Checkout Blocks “address format validation” is documented as shipping-only. Billing fields are not validated by that rule, so a buyer can ship to a street address and still bill a PO Box.

If you also need a street number on the address line (a separate sibling rule), Free AddressFence covers billing PO-box and street-number checks. Publish checkout validation that targets billing, then test a blocked address and an allowed street address.

Street number is a sibling rule — still not shipping-only

Blocking a PO Box answers “is this a PO Box?” Requiring a street number answers a different question: “does this street line include a house number?”

Shopify’s older Address Blocker / require street number rule was not migrated into the current Checkout Blocks address-format path. Merchants who still need “no bare street line without a number” need a separate check.

Treat street-number as a sibling of the billing PO Box job on this same page:

Billing PO Box rule and street-number rule
Rule What it rejects Billing vs shipping
PO Box on billing PO Box (and similar patterns you enable) on the card billing address Shipping-only native format validation does not cover billing
Street number A street line with no house number Same gap: do not assume a shipping format rule fixes billing

Do not copy every shipping address type onto billing unless that is the actual store policy. Turn street-number on only when bare lines without numbers are the problem you want to stop.

Suggested path:

  1. Install AddressFence from the App Store listing.
  2. Configure the billing PO Box rule; optionally enable the street-number check.
  3. Use the simulator on sample addresses before you publish.
  4. Publish to checkout validation.
  5. Run two live tests: a PO Box (or number-less street) on billing must error; a normal street billing address must pass.
  6. One-click rollback if the live function is wrong.

Does a shipping PO Box block also stop PO Box billing?

No. Native address format validation in Checkout Blocks can block PO Boxes and similar types on the shipping address. The Help Center states that billing address fields are not validated by that rule. A buyer can ship to a street address and still put a PO Box on the card billing address unless something else rejects billing.

Can I just require shipping and billing to match?

That native preference forces the two addresses to be the same. It is a fraud-control option, not a PO Box detector. It also blocks legitimate gift checkouts where shipping and billing should differ. If the matched address is a PO Box, both sides stay a PO Box. Use a billing-targeted checkout validation rule when the job is “no PO Box on billing.”

Do carrier restrictions or delivery profiles cover billing?

No. Hiding rates for PO Box shipping (carrier rules, delivery customizations) only affects how the order ships. Digital carts and “billing different from shipping” still collect a billing address. Native shipping tools do not publish a first-class “block PO Box on billing” toggle.

How do I block PO Box on billing at checkout?

Publish a checkout validation function that reads the billing address (not only shipping) and returns a field error on PO Box patterns. AddressFence (listing handle address-guard) is the App Store app this site already uses for PO Box blocking on checkout and billing. Open the listing, configure rules, publish to checkout validation, then test a blocked PO Box and an allowed street address. You can roll back the published function.

Will this also block military, diplomatic, or parcel-locker addresses?

Only if you turn those types on in the rule set. Native shipping address-format rules can include diplomatic, military, parcel locker, PO Box, and USPS gopost® — still on shipping, not billing. Do not copy every shipping block onto billing unless that is the actual policy. Test each type you enable.

Does blocking a PO Box on billing stop fraud?

No. It only rejects addresses that match the patterns you publish. It is not an AVS replacement, not a chargeback guarantee, and not legal advice. Pair it with the payment protections you already use. False positives happen if a street address contains “PO Box” in a second line; review tests before you leave the rule live.

What if the cart has no shipping address?

Digital or shipping-not-required carts still have a billing address. A shipping-only PO Box rule never runs on those checkouts. That is the case where a billing-targeted rule matters most. Confirm the function is published and that a test checkout with a PO Box billing line is rejected.
