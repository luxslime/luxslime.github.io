PO format rules

Requiring a PO number is not the same as checking format, prefix, regex, or length

Direct answer. Shopify B2B lets company buyers enter a purchase-order number and lets you set Net payment terms on a company location, but Shopify has no built-in no-code setting for PO format, prefix, regex, or length — a Cart and Checkout Validation function can read cart.poNumber (API 2026-04) and return field errors on $.cart.poNumber. B2B Terms & PO Guard is that validation function: it checks format, prefix, regex, length, and uniqueness, and previews any PO rule live against a sample number before you publish.

B2B Terms & PO Guard (Shopify App Store) validates PO numbers by format, prefix, regex, length, and uniqueness, sets deposit percentage guardrails, routes orders above a threshold for manual review, and previews any PO rule live against a sample number before you publish. This page is the format / prefix / regex / length slice — not uniqueness, deposit, threshold, or D2C no-op. Checkout enforcement runs on Plus B2B; PO rules work on every plan. This page is not legal advice.

Required is a boolean; format is a pattern

A require-PO rule only asks whether the field is empty. Format, prefix, regex, and length decide whether the string matches your company convention. Uniqueness is yet another rule against previously used numbers.

How to validate PO format before publish

  1. Decide which pattern you need (prefix, length, regex, or a combination).
  2. Configure the PO format rule in B2B Terms & PO Guard.
  3. Preview the rule live against sample numbers (valid and invalid).
  4. Publish only after the preview matches what company checkout should allow.

  • Uniqueness — stop reused PO numbers.
