Columns in the search CSV

Each search row is a public catalog hit, not a rank or a review. Sample rowType is podcast_search_result. The Actor README lists these output fields. There is no separate output schema on the Store page. CSV columns are the flattened dataset keys after you export from Console.

Column On a search CSV row
rowType Sample value podcast_search_result. Filter on this if a later run also writes chart or lookup rows.
collectionId Apple Podcasts collection ID. Use it for watchlists (lookupIds) or as podcastIds on Reviews Scraper.
showName Show title from the public catalog.
publisher Publisher / artist string on the catalog hit.
country ISO storefront used for that search (default us). Search uses one country per run.
rank Null on search rows. Rank belongs to chart requests, not keyword search.
episodeTitle Present only when includeEpisodes is true. Leave it false for a show list; this is not a full episode catalog or audio download.
sourceUrl Apple Podcasts page for the show.
fetchedAt Fetch timestamp for that row.

Rows can include warnings when a source is partial. The README discovery sample wraps meta plus rows[]; treat that as a docs envelope. Console CSV export is one row per dataset item. This Actor does not document contact emails, audience size, or download counts. Full field notes: Apple Podcasts dataset fields.

What “no Apple API key” means

Keyword search reads the public iTunes Search API. You do not register an Apple developer app, paste an Apple key into Input, sign in with an Apple ID, or open a private podcast dashboard. No proxy is required. The Actor is not affiliated with or endorsed by Apple.

That constraint is about Apple credentials. The run still executes on Apify, so you sign in or create an Apify account before Start. Public search is catalog metadata only: show IDs, names, publishers, and source URLs. It is not private Apple analytics, listener counts, or paid Apple Podcasts Connect reports.

What limit actually caps

The live default and Store prefill for limit is 3, not 50. Empty or omitted limit falls back to 3. The documented range is 1–200. On a search-only run, limit is the maximum number of podcasts requested from iTunes Search. It is not a guaranteed row count: iTunes can return fewer hits than limit, and result billing follows rows written to the default dataset.

The same top-level limit is also the default for chartRequests items that omit their own limit. Leave charts empty on this CSV path so the cap applies only to search. Pagination beyond limit is not documented. Keep the first export at 3, confirm the columns, then raise limit if you need a wider keyword list.

Download CSV in Console

Leave delivery on dataset. When the run succeeds, open the default dataset in the run view and export CSV (JSON is in the same view). Do not switch to webhook until you have reviewed those columns. See webhooks only after the file looks right. dryRun true runs without saving results, so there is no CSV to download.

When to leave this search CSV for Chart or Reviews

Stay on this Actor when the job is a keyword list of public shows. If the job is storefront Top Podcasts ranks or rank movement, leave the search CSV and use Apple Podcasts charts (or Apple Podcasts Chart Scraper for movement reports). If the job is public review text or ratings, take collectionId from this CSV and open reviews by storefront / Apple Podcasts Reviews Scraper. Search rows will not fill rank or review content for you.
