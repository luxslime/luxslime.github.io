Export Apple Podcasts episode metadata

Apple Podcasts Scraper can attach recent episode context to resolved shows, or snapshot official episode charts. It uses official Apple/iTunes endpoints. No proxy is required. Episode inclusion is a published boolean: includeEpisodes. Leave it off unless episode-level context is required; that path is slower.

Recent episodes versus episode charts versus RSS

Use this guide when the job is recent episode titles on resolved shows, or an episode-rank snapshot. Use a public RSS feed (or RSS & Atom Feed Extractor for many feeds) when you need a known show’s published catalog. Chart Scraper does not attach episode catalogs — that work stays on Apple Podcasts Scraper. Reviews Scraper does not return episode titles.

What you get

Episode-related rows are source-linked dataset items. Documented output fields include:

  • episodeTitle — present when recent episodes are included
  • collectionId — Apple Podcasts collection ID for the show
  • showName, publisher, country
  • sourceUrl — Apple Podcasts page
  • fetchedAt — fetch timestamp
  • rowType — row kind for downstream filters
  • rank — set on chart rows; not a search-rank field

The published input does not expose a per-show episode count, a date window, or a full-catalog dump. For the complete published history of a show you already know, read that show’s public RSS feed. See RSS vs Apple Podcasts Scraper.

Recent episodes on known shows

Resolve shows first (iTunes Search, charts, or iTunes Lookup IDs), then set includeEpisodes true. At least one of searchTerm, chartRequests, or lookupIds is required.

{
  "lookupIds": ["1535144780"],
  "country": "us",
  "includeEpisodes": true
}

Use this when a short look at what a resolved show is publishing is enough. It is not a substitute for archiving a feed.

Episode chart snapshot

To snapshot Apple’s episode rankings, use chartRequests with feedType set to podcast-episodes. Supported feedType values are podcasts and podcast-episodes. Per-item country overrides the default storefront.

{
  "chartRequests": [
    { "country": "us", "feedType": "podcast-episodes", "limit": 25 }
  ],
  "includeEpisodes": false
}

That chart request is a ranking snapshot, not a per-show episode list. Rankings differ by storefront. For several countries in one run, see multi-country chart and search notes. For Top Podcasts show-rank movement, use Apple Podcasts Chart Scraper instead of this episode-chart path.

Does includeEpisodes dump a show’s full catalog?

No. The published input does not expose a per-show episode count, a date window, or a full-catalog dump. includeEpisodes fetches recent episodes for each resolved podcast and is slower. For the complete published history of a show you already know, read that show’s public RSS feed.

How do I snapshot episode charts versus recent episodes?

To snapshot Apple’s episode rankings, use chartRequests with feedType podcast-episodes. That chart request is a ranking snapshot, not a per-show episode list. To attach recent episode titles to resolved shows, set includeEpisodes true on search, charts, or lookupIds.

When should I read public RSS instead?

When you already have a feed URL and need that show’s published catalog (titles, descriptions, dates, enclosures). RSS does not search Apple’s directory and does not include chart rank. RSS & Atom Feed Extractor parses known publisher feeds into URL lists; it is not Apple episode-chart search.

What episode-related fields are documented?

Documented output fields include episodeTitle (when recent episodes are included), collectionId, showName, publisher, country, sourceUrl, fetchedAt, rowType, and rank on chart rows. This Actor’s published input controls episode inclusion with the includeEpisodes boolean only.

How do I export the dataset after a run?

Leave delivery on dataset. After the run finishes, open the default dataset and export it (JSON or CSV from the dataset view). Switch delivery to webhook only after the payload shape is approved. Set dryRun true to test without saving results or sending webhooks.

Does Chart Scraper attach episode catalogs?

No. Chart Scraper does not attach episode catalogs — that work stays on Apple Podcasts Scraper. Reviews Scraper does not return episode titles. Use includeEpisodes or feedType podcast-episodes on Apple Podcasts Scraper.

Can I pass an RSS feed URL to includeEpisodes?

No. Published inputs are searchTerm, chartRequests, and lookupIds. includeEpisodes is a boolean on those source lanes. If you already have a public feed URL, read the feed directly or use RSS & Atom Feed Extractor.

Is feedType podcast-episodes a per-show episode list?

No. That chart request is a ranking snapshot, not a per-show episode list. Rankings differ by storefront. For a known show’s complete published history, read that show’s public RSS feed.

How is an includeEpisodes run priced?

Billing is pay-per-event. The live Store card is from $10.00 / 1,000 results. Published events are Actor Start at $0.005 and result at $0.01 per default-dataset item ($10.00 per 1,000). includeEpisodes is slower; it does not add a separate published event.

Does Reviews Scraper return episode titles?

No. Reviews Scraper reads public Customer Reviews RSS for podcastIds you already have. Episode titles on resolved shows belong on Apple Podcasts Scraper includeEpisodes.

Export workflow

  1. Open Apple Podcasts Scraper, then the Actor on the Apify Store.
  2. Choose a source lane: lookupIds (known shows), searchTerm (discovery), or chartRequests with feedType: "podcast-episodes" (episode ranks).
  3. Set includeEpisodes true only when you need recent episode titles on resolved shows. Keep the first run small.
  4. Leave delivery on dataset. After the run finishes, open the default dataset and export it (JSON or CSV from the dataset view).
  5. Switch delivery to webhook only after the payload shape is approved. Set dryRun true to test without saving results or sending webhooks.

Billing is pay-per-event: Actor start plus one result event per default-dataset item. The published Store price is $0.005 per Actor start and $10.00 per 1,000 dataset results ($0.01 per row).
