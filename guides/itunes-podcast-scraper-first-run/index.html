iTunes podcast scraper: cheapest Apple Podcasts first paid run

This page is the cheapest useful first paid run for Apple Podcasts / iTunes Scraper: Search, Charts, Episodes. It uses the official iTunes Search API. No proxy is required. It is not affiliated with or endorsed by Apple.

The live Store Quickstart uses the same input below. Published PPE is result $2.50 per 1,000 dataset items ($0.0025 per row) plus Actor Start $0.005. If that run writes 3 result rows and charges one Actor Start event, the estimate is about $0.0125.

Cheapest useful input

Paste this JSON. Leave chartRequests and lookupIds empty. Do not add maxEpisodesPerShow; it is not in the live schema.

{
  "searchTerm": "technology",
  "country": "us",
  "limit": 3,
  "includeEpisodes": false
}

At least one of searchTerm, chartRequests, or lookupIds is required. A first paid run only needs searchTerm. country is the ISO storefront (default us). limit is the maximum number of podcasts returned (1–200; schema default 50, prefill 3). includeEpisodes default is false.

Estimated cost from published PPE only

Billing is pay-per-event. You are not charged for Apify platform usage, only the fixed event price. Published events:

  • Actor Start — $0.005 when the Actor starts. Number of events charged depends on Actor memory (one event per GB, minimum one event).
  • result — $0.0025 per default-dataset item ($2.50 per 1,000 results).

What this first run returns

Search results are source-linked dataset items. Sample rowType is podcast_search_result. Documented fields include collectionId, showName, publisher, country, sourceUrl, and fetchedAt. rank is null on search rows; rank belongs to chartRequests.

Leave includeEpisodes false on the first paid run. That path is slower. This Actor does not document genre filters, review text, or pagination beyond limit.

What not to add yet

  • Do not raise limit until the three-row output is useful.
  • Do not set includeEpisodes true until you need recent episode titles.
  • Do not add chartRequests or lookupIds until search output is approved.
  • Do not invent maxEpisodesPerShow. It is not in the live input schema.

Why leave includeEpisodes false on the first run?

includeEpisodes fetches recent episode context for each resolved podcast and is slower. Leave it false until the show list is useful. The first paid run is a search-only check of collection IDs, show names, publishers, and source URLs.
