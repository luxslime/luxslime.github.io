Block PO boxes: native shipping-rate hide vs checkout validation vs AddressFence

Native Shopify can block a PO Box on shipping, and since 17 June 2026 Checkout Blocks address validation is available to all merchants for that ship-to job, but billing is not covered. AddressFence documents a billing-targeted rule, and merchants should not block every PO Box.

Three controls, three surfaces

Three controls see three surfaces: native shipping-rate hide decides whether a carrier offers a rate to a ship-to and never reads billing, while Checkout Blocks can block a PO Box on shipping for every merchant since 17 June 2026 but does not cover billing. AddressFence checkout validation can target billingAddress if the published function is set that way.

When you should not block all of them

A store that sells to people who only have a PO Box for delivery should keep ship-to boxes available. Blocking every PO Box, locker, military, or diplomatic type because a shipping-format list includes them is the wrong default. AddressFence does not decide that policy; the merchant enables types, publishes, and can roll the function back.

  • Leave PO Box shipping on when parcels really go to a box.
  • Do not copy locker, military, diplomatic, or USPS gopost® types onto billing unless that is the written policy.
  • Do not force shipping = billing just to “catch” a box. That blocks gift checkouts and still lets a matched PO Box through.
  • Digital or shipping-not-required carts never run a shipping-only rule. Decide whether billing is in scope at all before you publish.

Where AddressFence still differs

Use native Checkout Blocks when the job is a non-compliant shipping address — available to all merchants since 17 June 2026. Use AddressFence when the job is a field error on billing, or the sibling street-number check after Address Blocker sunset on 31 August 2026. Do not block every PO Box.

Install, publish only the types you mean, then prove one block

A merchant publishes a billing PO Box rule by installing AddressFence from apps.shopify.com/address-guard, turning on PO Box and only the extra types the store policy needs, targeting billing if that is the gap, publishing to checkout validation, then testing one address that must error and one street address that must pass.

  1. Open the AddressFence listing (apps.shopify.com/address-guard) and install it.
  2. Turn on PO Box (and only the extra types your policy needs). Target billing if that is the gap.
  3. Publish to checkout validation.
  4. Test one address that must error and one normal street address that must pass. Roll back if the live function is wrong.

Can Shopify checkout already block a PO Box?

Yes, on shipping: since 17 June 2026, Checkout Blocks address validation is available to all merchants and can block a PO Box on the shipping address, while billing address is not covered. Hiding carrier rates for a PO Box ship-to is a different control, because rate hide removes a rate and does not attach a field error to billing. Native Shopify can block PO boxes on shipping. The remaining gap is billing and edge cases, not “Shopify cannot block PO boxes.”

Should I block every PO Box?

No: do not turn on every address type just because a shipping format list includes them, and leave PO Box shipping available when buyers legitimately receive parcels at a box. Do not copy locker, military, or diplomatic types onto billing unless that is the store policy; gift checkouts also break if shipping and billing are forced to match.

Where does AddressFence still differ from native shipping-rate hide and checkout validation?

Native checkout can block non-compliant shipping addresses for every merchant since 17 June 2026. AddressFence pages on momiji-space document a billing-targeted rule and a sibling street-number check after Address Blocker sunset on 31 August 2026 (handle address-guard). Merchants should not block every PO Box. The PO Box comparison does not invent address line 2 or country-level coverage.

Does hiding shipping rates stop a PO Box on the card billing address?

No: carrier rules and delivery customizations decide whether a rate is offered to a ship-to, and digital carts plus billing-different-from-shipping still collect a billing address. Rate hide does not validate billing fields and does not attach a checkout field error on a PO Box used only for the card.

Does the PO Box comparison guarantee fewer chargebacks?

No: the PO Box comparison does not guarantee fewer chargebacks, because rejecting an address pattern is not AVS, not a fraud guarantee, and not legal advice. False positives happen if a street line contains “PO Box” as extra text, so test a blocked address and an allowed street address before leaving a rule live.
