Raw chart snapshot

The default path delivers source-linked chart_rank rows. Start with one country and a small limit.

{
  "countries": ["us"],
  "limit": 25,
  "delivery": "dataset",
  "dryRun": false
}

Published raw fields: actorName, rowType, billingEventName, country, rank, showId, showName, artistName, sourceUrl, fetchedAt, plus legacy aliases name, artist, and collectionId. There is no separate output schema on the Store page. README sample (placeholder show data):

{
  "actorName": "apple-podcast-chart-tracker",
  "rowType": "chart_rank",
  "billingEventName": "apify-default-dataset-item",
  "country": "us",
  "rank": 12,
  "showId": "123456",
  "showName": "Example Podcast",
  "artistName": "Example Network",
  "sourceUrl": "https://podcasts.apple.com/us/podcast/id123456",
  "fetchedAt": "2026-08-01T00:00:00.000Z",
  "collectionId": "123456",
  "name": "Example Podcast",
  "artist": "Example Network"
}

countries accepts at most 20 unique two-letter codes. Each country is fetched with a timeout and bounded retry. limit is capped at 200. genreId is optional (empty = overall chart; 1321 is the published News example).

Movement monitor

For recurring rank movement, set a stable monitorKey and generateMovementReport to true. The first baseline_only run stores state without dataset rows or charges.

{
  "countries": ["us", "gb"],
  "genreId": "1321",
  "limit": 50,
  "monitorKey": "weekly-news-us-gb",
  "generateMovementReport": true,
  "initialRunMode": "baseline_only",
  "maxChargeUsd": 3,
  "dryRun": false
}

A later poll emits at most one podcast_chart_movement_report row for all observed changes. Unchanged polls emit zero rows and zero charges. A failed source is not treated as a mass drop. emit_backfill reports the initial current positions once. Leave emitRawRows false unless the monitor also needs the legacy chart rows.

{
  "actorName": "apple-podcast-chart-tracker",
  "rowType": "podcast_chart_movement_report",
  "billingEventName": "podcast-chart-movement-report",
  "monitorKey": "weekly-news-us-gb",
  "initialRun": false,
  "fetchedAt": "2026-08-01T00:00:00.000Z",
  "changedCount": 1,
  "newCount": 1,
  "droppedCount": 0,
  "changes": [
    {
      "changeType": "changed",
      "country": "us",
      "showId": "123456",
      "showName": "Example Podcast",
      "previousRank": 18,
      "currentRank": 12,
      "rankDelta": 6,
      "sourceUrl": "https://podcasts.apple.com/us/podcast/id123456"
    }
  ]
}

State is isolated by monitorKey and is saved only after webhook and dataset delivery succeed. Use delivery: "webhook" only after the movement-report shape is validated. Webhook delivery does not replace dataset delivery.

How is Apple Podcasts Chart Scraper different from Apple Podcasts Scraper?

Chart Scraper is storefront Top Podcasts rankings only: raw chart_rank rows, or one movement report when a saved monitor sees new, changed, or dropped positions. It does not search by keyword, look up collection IDs, or attach episode catalogs. Apple Podcasts Scraper is the search, episode, and watchlist actor; its chartRequests path is a rank snapshot and does not emit movement reports. Apple Podcasts Reviews Scraper reads public Customer Reviews RSS for collection IDs you already have.

What does a raw chart snapshot contain?

Each delivered raw row has rowType chart_rank. Published fields include country, rank, showId, showName, artistName, sourceUrl, fetchedAt, plus legacy aliases name, artist, and collectionId. Sample rows are source-linked to an Apple Podcasts URL. There is no separate output schema on the Store page. Rank movement is descriptive evidence, not a forecast, audience estimate, or advertising guarantee.

When does a movement report emit, and what does it include?

Set a stable monitorKey and generateMovementReport to true. A baseline_only first run stores state with zero rows and zero charges. Later unchanged polls emit zero rows and zero charges when emitRawRows is false. A later poll that sees new, changed, or dropped positions emits at most one podcast_chart_movement_report row. That row includes monitorKey, changedCount, newCount, droppedCount, and a changes list with changeType, country, show identity, previousRank, currentRank, rankDelta, and sourceUrl. A failed source is not treated as a mass drop. emit_backfill emits one initial report of current positions.

How many countries and ranks can I request?

The published input schema has no required array. Runtime still fetches the default storefront when countries is omitted. additionalProperties is false. Live input schema fields:

Field Type Default Notes
countries string[] ["us"] ISO-3166-1 alpha-2 codes. At most 20 unique values. Schema prefill is us.
genreId string empty Optional Apple-internal genre ID. Empty = overall chart. 1321 is the published News example.
limit integer 50 Chart depth per country, capped at 200.
monitorKey string empty Stable state namespace. Movement reports need this plus generateMovementReport.
generateMovementReport boolean false Emit one report row only for new, changed, or dropped positions.
initialRunMode string baseline_only Enum: baseline_only or emit_backfill.
emitRawRows boolean false In movement mode, also deliver legacy chart_rank rows. Leave false for zero-charge unchanged polls.
maxChargeUsd number 3 Fail closed before delivery when the estimated charge exceeds the cap.
delivery string dataset Enum: dataset or webhook.
webhookUrl string — Required when delivery is webhook. Only http and https URLs are accepted.
dryRun boolean false Fetch and format without dataset, webhook, charge, or state delivery.

Do not send unpublished aliases such as searchTerm, lookupIds, includeEpisodes, chartRequests, feedType, podcastIds, or an RSS URL field. countries accepts at most 20 unique ISO-3166-1 alpha-2 codes per run (for example us, gb, jp, or de). Unsupported storefronts produce a warning and are never interpreted as a mass drop from the saved baseline. Storefronts differ: see charts and search by country for why a US chart is not a GB or JP chart.

How does Apple Podcasts Chart Scraper deliver dataset, webhook, and dry-run output?

delivery defaults to dataset and writes billable rows to the Apify default dataset. webhook sends the same payload to an http or https webhookUrl first, then writes those billable rows to the default dataset. A non-2xx webhook response fails the run before dataset delivery and prevents state commit. Webhook delivery does not replace dataset delivery. The published enum is dataset or webhook. dryRun fetches and formats the result without dataset, webhook, charge, or state delivery. Sibling webhook contracts differ: see Deliver Apple Podcasts results with webhooks.

Does Apple Podcasts Chart Scraper search by keyword, look up collection IDs, or attach episode catalogs?

No. Published inputs are countries, optional genreId, and limit, plus monitor fields. additionalProperties is false, so unpublished searchTerm, lookupIds, includeEpisodes, chartRequests, and feedType fields are not accepted. Use Apple Podcasts Scraper for keyword search, collection-ID watchlists, recent episodes, and chartRequests snapshots. Use Apple Podcasts Reviews Scraper for public ratings on IDs you already have.

Can Apple Podcasts Chart Scraper snapshot episode rankings with feedType podcast-episodes?

No. This Actor reads public Apple Podcasts/iTunes Top Podcasts chart JSON. The published schema has no feedType field. For official episode rankings, use Apple Podcasts Scraper chartRequests with feedType podcast-episodes. That path is a rank snapshot and does not emit movement reports. What is the difference between baseline_only and emit_backfill on a Chart Scraper monitor?

Both require a stable monitorKey with generateMovementReport true. baseline_only is the default initialRunMode: the first run stores state with zero dataset rows and zero charges. emit_backfill emits one initial podcast_chart_movement_report of the current positions once. Later polls emit at most one report when ranks are new, changed, or dropped. State is isolated by monitorKey and is saved only after webhook and dataset delivery succeed.

Can I pass a collection ID or an RSS feed URL into Apple Podcasts Chart Scraper?

No. additionalProperties is false. Published inputs do not accept lookupIds, podcastIds, searchTerm, or an RSS URL field. For collection-ID refresh use Apple Podcasts Scraper lookupIds. For a known show’s published catalog, read public RSS or use RSS & Atom Feed Extractor. For public ratings on IDs you already have, use Apple Podcasts Reviews Scraper. Does Chart Scraper genreId filter search results or collect review text?

No. genreId is an optional Apple-internal genre ID on Top Podcasts charts only (1321 is the published News example). Leave it empty for the overall chart. This Actor does not document genre filters on keyword search, and it does not collect review text. Apple Podcasts Scraper searchTerm has no published genre filter.
