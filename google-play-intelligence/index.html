How is Google Play App Scraper different from Chrome Web Store Extension Intelligence and Website Content Extractor?

Google Play App Scraper — Ratings, Installs & ASO (taroyamada/google-play-intelligence): This Actor reads public Google Play listing HTML/storefront data for package IDs or Play URLs and returns metadata, install ranges, pricing flags, and optional embedded review snippets. Review samples are limited to cards in the initial HTML. Not Apple App Store, Chrome Web Store, or a full Play review-pagination crawler. Not ranking/ASO keyword volume. Chrome Web Store Extension Intelligence is for Chrome extensions (input extensionUrls / searchTerms; Chrome Web Store; extension rows). Not Google Play packages. Website Content Extractor is for Generic page markdown (input urls; HTML body; markdown). Not Play storefront fields.

What input is required?

Live required fields: appUrls. exampleRunInput uses com.spotify.music plus a Duolingo Play URL, reviewLimit 5. Schema default reviewLimit 20; set 0 to skip samples. country/language default us/en.

Field Type Default Notes
appUrls array required empty App URLs or package IDs. Google Play app URLs or Android package identifiers to inspect.
country string us Storefront country. Two-letter Google Play storefront code used for listing requests.. minLength=2
language string en Language. Language code used for listing requests.. minLength=2
reviewLimit integer 20 Embedded review sample limit. Maximum embedded public review samples to keep per app. Set to 0 to skip review samples.
timeoutMs integer 20000 Request timeout (ms). HTTP timeout per Google Play listing request.
delivery string dataset Delivery. Where to send results: dataset or webhook.
webhookUrl string empty Webhook URL. Webhook URL to POST results to when delivery=webhook.
dryRun boolean false Dry run. Run extraction without pushing rows to the dataset.

Published Store example run input (omitted fields take schema defaults):

{
  "appUrls": [
    "com.spotify.music",
    "https://play.google.com/store/apps/details?id=com.duolingo"
  ],
  "country": "us",
  "language": "en",
  "reviewLimit": 5,
  "timeoutMs": 20000,
  "delivery": "dataset",
  "dryRun": false
}

How do dataset, webhook, and dry-run delivery work?

delivery defaults to dataset on the live schema. Dataset output is the billable surface when rows are written. webhookUrl is used when delivery is webhook (and typically not during dryRun). dryRun true validates or samples without the usual dataset/webhook side effects described on the Store schema.
