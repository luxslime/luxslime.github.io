What input is required?

Live required fields: repositories. exampleRunInput watches apify/crawlee (releases+tags) and axios/axios (releases+tags+changelog). Keep snapshotKey stable. datasetMode default changes_only. delivery enum includes unused email placeholder.

Field Type Default Notes
repositories array required empty Repositories (one summary row each). List of repositories to monitor. Each item supports id, name, repo, criticality, owner, tags, modes, releaseUrl, releaseNotesUrl, tagsUrl, changelogUrl, and optional surfaces overr…
requestTimeoutSeconds integer 30 Request timeout (seconds). HTTP request timeout per monitored source.
userAgent string empty Custom User-Agent. Optional User-Agent header for upstream requests.
maxChars integer 35000 Global max chars per source. Upper bound for extracted text per monitored source.
delivery string dataset Delivery mode. Where to send summary-first repository results.
datasetMode string changes_only Dataset mode. Choose every repository row, only changed rows, or only action-needed rows.
webhookUrl string empty Webhook URL. Required when delivery is webhook.
notifyOnNoChange boolean false Notify even if no change. When false, webhook delivery skips when there are no changed or action-needed repository summaries.
snapshotKey string github-release-monitor-snapshots Snapshot key. Key used for recurring snapshot persistence. Keep it stable so release and changelog drift stays comparable over time.
diffMode string line_summary Diff mode. Choose between line-level change summaries for reviewer context or hash-only detection when you only need alerting.
summaryMaxLines integer 12 Max diff lines per source. Maximum added and removed lines retained in each source change summary.
concurrency integer 2 Concurrency. Maximum number of monitored sources processed in parallel.
batchDelayMs integer 250 Inter-batch delay (ms). Delay between processing batches to reduce rate-limit pressure.
nowIso string empty Override current time (ISO). Optional deterministic timestamp override.
dryRun boolean false Dry run. Skip snapshot persistence and side-effect delivery.

How do dataset, webhook, and dry-run delivery work?

delivery defaults to dataset on the live schema. Dataset output is the billable surface when rows are written. webhookUrl is used when delivery is webhook (and typically not during dryRun). dryRun true validates or samples without the usual dataset/webhook side effects described on the Store schema. datasetMode can limit emits to changes_only versus all. Unchanged runs that write zero default-dataset rows typically charge $0.00 on current PPE.
