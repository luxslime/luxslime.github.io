How is Site QA Content Report different from Website Content Extractor and Article Content Extractor?

Site QA Content Report (taroyamada/site-qa-content-report-scraper): Audit public web pages for content quality issues and generate source-linked QA report rows. Not a page-to-markdown dump (use Website Content Extractor). Not article boilerplate cleanup (use Article Content Extractor). Not a RAG readiness scoring pack. You supply the URLs. Website Content Extractor is for One-shot page-to-markdown (input urls; Page HTML; Markdown/text). Not content-quality issue reports. Article Content Extractor is for News/blog HTML cleanup (input urls; Article HTML; Headline/byline/body). Not site QA content reports. Website RAG Readiness Audit is for RAG coverage and chunking risk (input urls / domain; Public pages; RAG snapshot/readiness reports). Not generic content-quality issue rows.

What input is required?

Live required fields: urls. Published exampleRunInput is shown below.

Field Type Default Notes
urls any[] ["https://example.com/?siteQaCanary=content-v2"] Public page URLs. Public URLs that you are allowed to audit. Required.
maxPages integer 10 Max pages. Maximum number of input pages to check. minimum=1 maximum=100
maxLinksPerPage integer 25 Max links per page. Maximum links to check per page for URL health workflows. minimum=1 maximum=250
emitPageRows boolean false Emit raw page rows. Emit optional raw page snapshot rows in addition to value-event issue/report rows.
generateReport boolean true Generate report row. Generate a site-level report row.
emitExport boolean false Generate export row. Generate an export row for handoff workflows.
emitUnchanged boolean false Emit unchanged rows. When false, repeated unchanged runs emit zero rows and zero charges.
dryRun boolean false Dry run. Emit local sample rows without charging.

Published Store example run input (omitted fields take schema defaults):

  "urls": [

  "maxPages": 1,
  "maxLinksPerPage": 1,
  "dryRun": false
