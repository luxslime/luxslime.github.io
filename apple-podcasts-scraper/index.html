Use cases

Search quickstart

Keyword search is the lowest-friction first run. Set searchTerm. At least one of searchTerm, chartRequests, or lookupIds is required. country is the ISO storefront for the search (default us). limit is the maximum number of podcasts returned (1–200; default 50). Keep the first run small.

{
  "searchTerm": "founder podcast",
  "country": "us",
  "limit": 10,
  "includeEpisodes": false
}

Sample rowType is podcast_search_result. Published fields include collectionId, showName, publisher, country, sourceUrl, and fetchedAt. rank is null on search rows. README discovery-row example (placeholder show data):

    "actorName": "apple-podcast-scraper",

    "totalRows": 1

  "rows": [
    {
      "actorName": "apple-podcast-scraper",

This Actor does not document genre filters, review text, contact emails, or pagination beyond limit. After a search run, pass collection IDs into a iTunes Lookup watchlist refresh. See Apple Podcasts search discovery (iTunes Search API).

Chart snapshot

Use chartRequests for official Apple rankings. Each item can set country, feedType, and limit. Supported feedType values are podcasts and podcast-episodes. If an item omits limit, the top-level limit applies. Per-item country overrides the default storefront.

{
  "chartRequests": [
    { "country": "us", "feedType": "podcasts", "limit": 25 }
  ],
  "includeEpisodes": false
}

Each chart row can include rank, collectionId, show identifiers, sourceUrl, and fetchedAt. This is a snapshot: the Actor does not compute rank movement between runs. For new, changed, or dropped positions on a saved monitor, use Apple Podcasts Chart Scraper. See How to get Apple Podcasts chart metadata from Apple/iTunes endpoints.

How is Apple Podcasts Scraper different from Chart Scraper and Reviews Scraper?

Apple Podcasts Scraper is the search, episode, and watchlist actor. It finds public shows through official Apple/iTunes endpoints: searchTerm, chartRequests snapshots, lookupIds, and optional recent episodes. It does not emit rank movement reports or review rows. Apple Podcasts Chart Scraper is storefront Top Podcasts ranks and optional movement reports. Apple Podcasts Reviews Scraper reads public Customer Reviews RSS for collection IDs you already have.

What input is required to start a run?

The published input schema has no required array. Runtime and schema description still require at least one of searchTerm, chartRequests, or lookupIds. additionalProperties is false. Live input schema fields:

Field Type Default Notes
searchTerm string — iTunes Search API keyword. Schema prefill is technology.
chartRequests array [] Items can set country, feedType (podcasts or podcast-episodes), and limit.
lookupIds array [] Numeric Apple Podcasts collection IDs for iTunes Lookup.
country string us Default ISO storefront for search and lookup. Charts can override per item.
limit integer 50 1–200. Caps search and chart items that omit their own limit. Schema prefill is 3.
includeEpisodes boolean false Fetch recent episodes for each resolved podcast (slower).
delivery string dataset Enum: dataset or webhook.
webhookUrl string — Used when delivery is webhook.
dryRun boolean false Runs without saving results or sending webhooks.

Do not send unpublished aliases such as an RSS feed URL field, genreId, maxEpisodesPerShow, or webhook as a delivery value. Keep the first run small, then raise limit after the output is useful.

What does a result row contain?

Output is source-linked dataset rows. The published README field list is rowType, collectionId, showName, publisher, country, rank, episodeTitle, sourceUrl, and fetchedAt. Sample search rowType is podcast_search_result. rank is null on search rows. Rows also include warnings when a source is partial, and stable IDs when the workflow supports recurring checks. There is no separate output schema on the Store page. See Apple Podcasts dataset fields.

How do I export episode metadata?

Set includeEpisodes to true to fetch recent episodes for each resolved podcast. That path is slower. For official episode rankings, use chartRequests with feedType podcast-episodes. After a dataset run, export the default dataset (JSON or CSV from the dataset view). The published input does not expose a per-show episode count, a date window, or a full-catalog dump; for a known show’s complete feed, read public RSS. See the episode metadata export workflow, RSS vs Apple Podcasts Scraper, and RSS & Atom Feed Extractor when you already have public feed URLs to parse into item lists.

Can I pull charts or search for more than one country?

Charts can. chartRequests is an array; each item can set its own country (ISO codes such as us, gb, jp). Search and lookup use a single default country per run. Rankings and search results differ by storefront, so compare rows by the country field instead of mixing ranks. This Actor’s chartRequests path is a rank snapshot and does not emit movement reports. Does keyword search return chart rank or review text?

No. rank is null on search rows. This Actor does not document review text on the search path. For official rankings use chartRequests on this Actor, or Apple Podcasts Chart Scraper when you need a movement report. For public ratings on IDs you already have, use Apple Podcasts Reviews Scraper.

Can I pass a public RSS feed URL into Apple Podcasts Scraper?

No. Published inputs are searchTerm, chartRequests, and lookupIds. additionalProperties is false, so an unpublished RSS URL field is not accepted. RSS is used internally when includeEpisodes is true. If you already have a public feed URL and need that show’s published catalog, read the feed directly or use RSS & Atom Feed Extractor. See RSS vs Apple Podcasts Scraper and RSS feed vs iTunes Search.

Does includeEpisodes dump a show's full episode catalog?

No. includeEpisodes fetches recent episode context for each resolved podcast and is slower. The published input does not expose a per-show episode count, a date window, or a full-catalog dump. For official episode rankings, use chartRequests with feedType podcast-episodes. For a known show’s complete published history, read public RSS. See the episode metadata export workflow.

What happens on an empty or no-change watchlist poll?

Empty no-change watchlist polls are described as avoiding payable default-dataset writes when nothing is saved. Result events are charged per default-dataset item ($0.01 each; $10.00 per 1,000). Actor Start is a separate $0.005 event charged when the Actor starts (one event per GB, minimum one event). Dry runs do not save results or send webhooks. See iTunes Lookup watchlist refresh.

Can I filter Apple Podcasts search results by genre?

No. This Actor does not document genre filters on searchTerm. Apple Podcasts Chart Scraper accepts an optional genreId for Top Podcasts charts. This Actor’s search and lookup paths use country plus searchTerm or lookupIds only. Pagination beyond limit is not documented.

What should I do with collection IDs after a search run?

Pass collection IDs into lookupIds for a watchlist refresh through the iTunes Lookup API. You can take an ID from an Apple Podcasts URL (id290783428 → 290783428). Use those IDs as podcastIds on Apple Podcasts Reviews Scraper if you need public ratings. This Actor does not emit review rows or rank-movement reports from a search run.
