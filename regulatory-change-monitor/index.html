How is Regulatory Alerts Scraper different from Federal Register Scraper and SaaS Pricing Tracker?

Regulatory Alerts Scraper (taroyamada/regulatory-change-monitor): This Actor fetches public government pages you list in targets[], snapshots extracted text, and emits source-linked change rows when filtered text drifts or watch terms hit. Live input is targets, not Federal Register API feeds. Not the Federal Register document API. Not authenticated portals. Not legal advice. Public HTML only; bot walls may block fetches. Federal Register Scraper is for Federal Register docs (input feeds / watchTerms; federalregister.gov API; FR digest rows). Not page-HTML regulatory crawls. SaaS Pricing Tracker is for Pricing/terms diffs (input targets[]; public SaaS pages; SaaS change rows). Not B2B competitor pricing packs. Docs & Changelog Drift Scraper is for Docs/changelog diffs (input doc URLs; public docs HTML; drift rows). Not Federal Register rules.

What input is required?

Live required fields: targets. Published exampleRunInput is shown below. Summary-first monitoring for official regulator update feeds, government bulletin pages, and public compliance notices

Field Type Default Notes
targets any[] required empty required Targets (one digest row each). List of regulatory sources to monitor. Each item supports id, name, jurisdiction, regulator, domain, criticality, owner, tags, feedUrl, bulletinUrl, noticesUrl, and optional sourcePages[].
requestTimeoutSeconds integer 30 Request timeout (seconds). Maximum time to wait for one public source request. min=5 max=120
userAgent string empty Custom User-Agent. Optional custom User-Agent string for public HTTP requests.
maxChars integer 35000 Global max chars per source. Upper bound for extracted text per monitored source before hashing and diff. min=1000 max=200000
delivery string enum dataset Delivery mode. Choose whether digest rows should be written to the dataset, posted to a webhook, or reserved for a future email path. enum: dataset, webhook, email
datasetMode string enum changes_only Dataset mode. Controls which target rows are persisted: only action-needed rows, only changed rows, or every monitored target. enum: action_needed, changes_only, all
webhookUrl string empty Webhook URL. Webhook destination when delivery is set to webhook.
notifyOnNoChange boolean false Notify even if no change. If true, webhook delivery still fires even when no target crosses the change threshold.
snapshotKey string regulatory-change-monitor-snapshots Snapshot key. Stable key used to load and save previous source snapshots between recurring runs.
diffMode string enum line_summary Diff mode. Use line summaries for concise change evidence or hash-only mode for simple changed/unchanged detection. enum: line_summary, hash_only
summaryMaxLines integer 12 Max diff lines per source. Maximum number of added and removed lines to keep in each source-level change summary. min=5 max=50
concurrency integer 2 Concurrency. How many public sources the actor may fetch in parallel. min=1 max=10
batchDelayMs integer 500 Inter-batch delay (ms). Delay between fetch batches to soften load on public regulatory sources. min=0 max=10000
nowIso string empty Override current time (ISO). Optional ISO timestamp override for deterministic fixture tests or proof snapshots.
dryRun boolean false Dry run. If true, the actor skips snapshot writes and remote delivery while still producing local output.

How do dataset, webhook, and dry-run delivery work?

delivery defaults to dataset on the live schema. Dataset output is the billable surface when rows are written. webhookUrl is used when delivery is webhook (and typically not during dryRun). dryRun true validates or samples without the usual dataset/webhook side effects described on the Store schema. datasetMode can limit emits to changes_only / changed_only / action_needed versus all. Unchanged runs that write zero default-dataset rows typically charge $0.00 on current PPE.
