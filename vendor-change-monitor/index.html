Public vendor pricing and terms diffs for procurement watchlists

SaaS Vendor Pricing & Page Change Scraper headless-crawls public vendor pricing, terms, feature, security, and status pages you list. It snapshots text, emits semantic diffs (previous vs current prices, plan and feature changes), severity, recommended actions, and section or PDF text. The first run seeds a baseline; later runs prove diffs. It is not the simpler targets[] SaaS page watcher — that job is SaaS Pricing Tracker — and it is not one-shot page markdown (Website Content Extractor).

How is SaaS Vendor Pricing & Page Change Scraper different from SaaS Pricing Tracker and B2B Pricing Scraper?

SaaS Vendor Pricing & Page Change Scraper (taroyamada/vendor-change-monitor) takes a vendors JSON array of id, name, criticality, owner, tags, and urlPacks. Live PPE is $0.01 per delivered new or changed monitoring result row ($10.00 / 1,000). Unchanged runs are free. SaaS Pricing Tracker uses targets[] of public SaaS pages and bills SaaS change rows. B2B Pricing Scraper uses competitors[] pricing pages. Website Change Monitor is generic URL diffs. Use this Actor for vendor packs. Use SaaS Pricing Tracker for a flat target list. Use B2B Pricing Scraper for competitor price pages.

What input is required?

vendors is required. Prefill shape is one vendor (Stripe) with pricing and terms packs; each page has id, name, url, includePatterns, and excludePatterns. Live schema also includes requestTimeoutSeconds (default 30, min 5, max 120), userAgent, maxChars (default 30000, min 1000, max 200000), delivery (dataset, webhook, or email; default dataset), datasetMode (action_needed, changes_only, all; default changes_only), webhookUrl, notifyOnNoChange (default false), snapshotKey (default vendor-pricing-terms-watch), diffMode (line_summary or hash_only; default line_summary), summaryMaxLines (default 12, min 5, max 50), concurrency (default 3, min 1, max 10), batchDelayMs (default 500), nowIso, and dryRun (default false). README Input Examples that send urls or sectionSelector are not live schema fields.

How do dataset, webhook, and dry-run delivery work?

delivery defaults to dataset and also accepts webhook or email. webhookUrl is required when delivery is webhook. notifyOnNoChange defaults to false, so webhook skips when there are no changed digests and no action-needed items. dryRun previews without persisting snapshots or sending alerts. datasetMode changes_only is the default; all is the first-paid path when you need a delivered row on first success.

Limits to keep in mind

  • vendors required. Public pages only; no authenticated billing portals.
  • Unchanged runs are free on the live card; first changes_only run often only seeds baseline.
  • README examples that send urls or sectionSelector are not live schema fields.
  • Not a visual QA product and not legal advice.
  • Respect vendor site terms, robots.txt, and rate limits.
