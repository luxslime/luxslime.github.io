Query Google News RSS for localized headlines and article URLs

Google News Scraper discovers fresh article URLs by querying Google News RSS. It returns localized headlines, publisher names, timestamps, and short snippets, then deduplicates overlapping links across queries so you can feed URLs into a downstream extraction step. It is a query-driven discovery surface, not known-publisher feed XML parsing, not an HTML cleaner, and not a full-article scraper.

How is query-based Google News RSS different from known-publisher feed XML and from article HTML cleanup?

This Actor is query-based Google News discovery. Required input is queries (maximum 50 search terms). It reads Google News RSS for those queries and localizes with language (default en) and country (default US). RSS & Atom Feed Extractor is known-publisher feed discovery: you already have public RSS or Atom URLs and pass them in feedUrls (maximum 50). Article Content Extractor is HTML cleanup: it fetches article-shaped news, blog, newsroom, and press pages (maximum 300 URLs) and returns headline, byline, publish date, article body, excerpt, and hero image. Website Content Extractor cleans docs, pricing, policy, or product pages that are not article-shaped. Use this Actor when you do not have feed URLs yet and want broader query-based discovery.

Does Google News Scraper return full article bodies or clean HTML?

No. Google News Scraper is a discovery layer only. It does not return full article bodies and it does not clean HTML. Each row is metadata plus a direct article URL. Use Article Content Extractor to extract article bodies from those URLs. Use Website Content Extractor when a discovered URL is a docs, product, or policy page rather than an article. The published README FAQ states: this actor discovers URLs and returns metadata only.

Which fields does a Google News RSS article row include?

The published README output table lists title (article headline), link (direct article URL for downstream cleanup), source (publisher name), pubDate (original RSS publish date), pubDateISO (ISO timestamp version of pubDate), description (short Google News snippet), and query (the search query that surfaced the row). There is no published full-article text field. That table is the published field inventory, not a live coverage guarantee for every query.

Why query Google News RSS instead of scraping the Google News HTML interface?

The published README FAQ positions the RSS surface as lighter, more stable, and better suited for recurring discovery runs than scraping the Google News UI. This Actor queries Google News RSS, not the Google News HTML interface, and does not require a paid news API. Key features in the README are query-based discovery from Google News RSS without a paid API, localization by language and country, deduplication across queries, and a lightweight feeder step before deeper extraction.

How do language and country localize Google News RSS results?

language defaults to en (schema description: Language code, for example en, ja, de). country defaults to US (schema description: Country code, for example US, JP, GB). Together they tune Google News RSS for a region. The published README Input Examples include a localized JP run with language ja, country JP, and query 人工知能. This page is a search surface; RSS & Atom Feed Extractor has no language or country fields because it reads feed URLs you already have.

Does the live schema accept maxItemsPerQuery or dedupeAcrossQueries?

No. The live required field is queries. Live names are maxItems (Max Items per Query; 1–100, default 25) and deduplicate (Remove duplicate article URLs across queries; default true). README Input Examples that show maxItemsPerQuery or dedupeAcrossQueries are not live input names. Do not send unpublished aliases, feedUrls, or article-page urls lists.

How do dataset delivery, webhookUrl, and dryRun work for Google News discovery?

delivery defaults to dataset (How to deliver results). Live enum values are dataset and webhook; dataset_and_webhook is not a live enum value on this Actor. Set delivery to webhook and supply webhookUrl when you want webhook delivery. The live schema description for webhookUrl is: URL to POST discovery results when delivery=webhook. dryRun defaults to false and runs without saving results. The live schema description for dryRun is: Run without saving results.

How does cross-query deduplicate treat overlapping article URLs?

deduplicate defaults to true. The live schema description is: Remove duplicate article URLs across queries. Keep that default when several search terms surface the same article URL. Set it false only when you need one row per originating query even if the link repeats.

Can I pass publisher feed URLs or article page URLs into Google News Scraper?

No. Required input is queries: Google News search terms (maximum 50). Known-publisher RSS or Atom XML URLs belong on RSS & Atom Feed Extractor as feedUrls. Article-shaped HTTP(S) pages belong on Article Content Extractor as urls. Docs, pricing, policy, or product pages belong on Website Content Extractor. After this Actor returns article links, send news, blog, and press URLs to Article Content Extractor.

Does Google News Scraper crawl news sites, open a browser, or parse sitemap.xml?

No. It queries Google News RSS for the keywords you supply. It does not scrape the Google News HTML interface, it does not crawl entire news sites blindly, it does not use browser automation, and it does not parse sitemap.xml URL inventories.
