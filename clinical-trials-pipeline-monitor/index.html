How is ClinicalTrials.gov Sponsor Pipeline Scraper different from PubMed Literature Watch and Biomedical Trial Literature Evidence Report?

ClinicalTrials.gov Sponsor Pipeline Scraper (taroyamada/clinical-trials-pipeline-monitor): This Actor queries the official ClinicalTrials.gov API v2 with a watchlist of condition/phase/status queries, flags sponsor watch-terms, and emits digest rows for new or changed studies. No API key is required. Not a patient-matching, IRB, or recruitment-operations tool. Not PubMed literature or NIH Reporter awards. Results are as-published CT.gov records, not medical advice. PubMed Literature Watch is for PubMed citation metadata watches (input search terms / PMIDs; NCBI PubMed; citation rows). Not CT.gov recruitment pipelines. Biomedical Trial Literature Evidence Report is for Capped evidence reports across trial/literature sources (input report inputs; linked public biomedical sources; evidence rows/reports). Not a raw CT.gov watchlist digest. NIH Research Funding Landscape Report is for NIH Reporter award landscape (input org/term filters; NIH Reporter; award rows/reports). Not trial recruitment status.

What input is required?

Live required fields: watchlist. exampleRunInput uses one diabetes PHASE3/4 recruiting query plus sponsor watchTerms, datasetMode all, notifyOnNoNew true. Schema default datasetMode is new_only and notifyOnNoNew false.

Field Type Default Notes
watchlist array required empty Watchlist queries (required). One entry per monitored query. Each produces one digest row in the output. At minimum set id, name, and condition. Add recruitmentStatus to narrow the result stream.. item object fields: …
watchTerms string empty Watch terms — sponsor / PI / institution names (comma-separated). Sponsor names, principal investigators, or institution names to flag in study digests. Any study matching a watch term receives a watch_term_hit signal…
maxStudiesPerQuery integer 50 Max studies per query. Upper bound on studies fetched per query per run. Increase for discovery; keep lower for recurring digest runs.
delivery string dataset Delivery mode. dataset stores results in the Apify dataset. webhook posts the digest JSON to webhookUrl.
webhookUrl string empty Webhook URL (required when delivery=webhook). POST target for trial digest payload. Leave empty for dataset delivery.
datasetMode string new_only Dataset output mode. all emits every query digest row. action_needed emits only queries with watch-term hits or new recruiting studies. new_only emits only queries with studies not seen in the previous run.
snapshotKey string clinical-trials-monitor-state Snapshot key for recurring state. Stable key used to persist seen study NCT IDs across recurring runs so new_only and action_needed modes stay comparable. Use the same key across scheduled runs.
clinicalTrialsApiUrl string https://clinicaltrials.gov/api/v2/studies ClinicalTrials.gov API URL. ClinicalTrials.gov API v2 studies endpoint. No API key required.
requestTimeoutSeconds integer 30 HTTP request timeout (seconds). Timeout for each API request.
notifyOnNoNew boolean false Emit digest even when no new studies found. When true, every query always produces a digest row even if no new studies were found. When false, queries with no new studies are omitted.
dryRun boolean false Dry run (skip snapshot writes and webhook delivery). Validate and fetch without persisting state or posting webhooks. Safe for testing input shapes.
nowIso string empty Override current time (ISO string, for testing). Set to a fixed ISO timestamp to make runs deterministic against fixture data.
fixtureDir string empty Fixture directory (testing). Directory containing JSON fixture files for offline tests. Files should be named <queryId>.json.

How do dataset, webhook, and dry-run delivery work?

delivery defaults to dataset on the live schema. Dataset output is the billable surface when rows are written. webhookUrl is used when delivery is webhook (and typically not during dryRun). dryRun true validates or samples without the usual dataset/webhook side effects described on the Store schema. datasetMode can limit emits to changes_only versus all. Unchanged runs that write zero default-dataset rows typically charge $0.00 on current PPE.
