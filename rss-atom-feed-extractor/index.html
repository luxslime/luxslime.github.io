Parse known-publisher RSS and Atom XML into filtered item URL lists

RSS & Atom Feed Extractor aggregates public RSS and Atom XML feeds you already have into structured JSON so you can discover fresh item URLs from blogs and newsrooms before a downstream scraper runs. It parses trusted feed XML, applies optional OR-based keyword filters, deduplicates links across sources, and returns item URLs with titles, dates, and summaries. It is not an HTML article extractor, not a Google News query surface, and it does not crawl a site to find new pages.

What public RSS and Atom XML does this Actor parse?

Public RSS and Atom XML feeds you already have. Required input is feedUrls (maximum 50 per run; schema description: Public RSS/Atom URLs to monitor). The Actor parses feed XML and returns feed items — titles, item URLs, publication timestamps, summaries, encoded content when available, and categories or tags. It does not crawl website HTML, it does not query Google News, and it does not extract full article bodies from those item links. Authenticated or HTML-only pages are not feed input.

How is known-publisher feed XML different from Google News query RSS and from article HTML cleanup?

This Actor is a known-publisher feed discovery layer: you already have public RSS or Atom URLs and pass them in feedUrls. Google News Scraper is query-based discovery: required input is queries (maximum 50 search terms), localized with language and country, reading Google News RSS rather than publisher feeds you supply. Article Content Extractor is HTML cleanup: it fetches article-shaped news, blog, newsroom, and press pages (maximum 300 URLs) and returns headline, byline, publish date, article body, excerpt, and hero image. Website Content Extractor cleans docs, pricing, policy, or product pages that are not article-shaped. Send this Actor's returned links to those extractors when you need full page text.

What live input does RSS & Atom Feed Extractor require?

The live OpenAPI input schema requires feedUrls. Optional fields are keywords, maxItemsPerFeed, deduplicate, timeoutMs, delivery, webhookUrl, and dryRun.

Which fields does a parsed RSS or Atom item include?

The published README output table lists source (feed URL that produced the row), title, link (item URL for downstream extraction), pubDate (original feed date), pubDateISO (ISO timestamp version of pubDate), description (summary text from the feed), content (encoded content when available), categories (categories or tags from the feed), and matchedKeywords (keywords that matched the row). That table is the published field inventory, not a live coverage guarantee for every feed.

Published README sample:

  "source": "https://openai.com/news/rss.xml",
  "title": "The next evolution of the Agents SDK",
  "link": "https://openai.com/index/the-next-evolution-of-the-agents-sdk",
  "pubDate": "Wed, 15 Apr 2026 10:00:00 GMT",
  "pubDateISO": "2026-04-15T10:00:00.000Z",
  "description": "OpenAI updates the Agents SDK with native sandbox execution...",
  "matchedKeywords": ["ai", "agents"]
}

That sample is the published README illustration of a filtered item, not a live coverage guarantee. After you confirm recent item URLs, send article, news, and blog links to Article Content Extractor and docs, product, or policy links to Website Content Extractor.

Does feed XML parsing return cleaned article bodies?

No. This Actor is a feed discovery layer, not a full-content extractor and not an HTML cleaner. It reads RSS or Atom XML. Use Article Content Extractor on returned news, blog, and press links. Use Website Content Extractor on returned docs, product, pricing, policy, or help-center links. Encoded content in the feed row, when present, is still feed XML content, not a cleaned article-body extract.

How does OR-based keyword filtering attach matchedKeywords?

keywords is an optional include-list. Matching is OR-based: any matched keyword keeps the item. Filtered rows include a matchedKeywords array so you can see which terms triggered the row. There is no exclude list in the published input schema. An empty keywords list does not apply that include filter. The README FAQ states you can see why an item matched via matchedKeywords.

When should I pass feedUrls instead of Google News queries?

Pass feedUrls here when you already know the publishers you trust and have their public RSS or Atom URLs. Use Google News Scraper when you do not have feed URLs yet and want broader query-based discovery. This page is not a search surface: it has no language or country localization fields. Google News Scraper localizes with language (default en) and country (default US).

Does the live schema accept feeds, onlyNewSinceLastRun, or a snapshot key?

No. The live required field is feedUrls. The published OpenAPI schema does not expose a feeds alias, onlyNewSinceLastRun, or snapshotKey. README illustrations that show a feeds array or a delta-only snapshotKey run are not live input names. Send feedUrls, not feeds.

How do dataset delivery, webhookUrl, and dryRun work for this feed Actor?

delivery defaults to dataset (Where to send results: dataset or webhook). Set delivery to webhook and supply webhookUrl when you want webhook delivery. Live enum values are dataset and webhook; dataset_and_webhook is not a live enum value on this Actor. dryRun defaults to false and runs without saving results. The live schema description for dryRun is: Run without saving results.

How does cross-feed deduplicate treat duplicate item links?

deduplicate defaults to true. The live schema description is: Remove duplicate links across feeds. Keep that default when several publishers syndicate the same item URL. Set it false only when you need one row per source feed even if the link repeats.
