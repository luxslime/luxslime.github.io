Clean docs, pricing, product, and help-center pages into markdown

Website Content Extractor fetches public docs, pricing, product, policy, and help-center URLs and returns cleaned markdown, text, or HTML. Use it as a bounded source step for content QA, indexability checks, and RAG datasets — not as a ranking tool or a full-site crawler. For news, blog, newsroom, or press URLs, use Article Content Extractor. For head Open Graph, robots, and JSON-LD issue audits, use Meta Tag & OpenGraph Scraper.

Use this page when the URLs are broad site pages: documentation, product, pricing, policy, or help-center. Use cases

  • Turn documentation URLs into markdown or plain text for content QA and docs audits.
  • Produce source content for title, metadata, thin-content, and page-quality checks.
  • Provide page-level source material for indexability work (robots, sitemap, canonical, noindex, schema, crawler access).
  • Generate bounded inputs for website RAG readiness audits.
  • Pull product and pricing pages as a low-cost source step before Site QA or RAG reporting.
  • Support recurring change detection with stable identifiers and fetch timestamps.

The published README also positions the Actor for AI builders, content ops, SEO teams, and documentation teams that supply public pages they own or are allowed to audit. Route news, blog, and article URLs to Article Content Extractor. This Actor is for broad site pages (max 200 URLs).

How is Website Content Extractor different from Article Content Extractor and Meta Tag & OpenGraph Scraper?

Website Content Extractor is the bounded HTML cleaner for public docs, product, pricing, policy, and help-center pages (urls, maximum 200). It returns cleaned markdown, text, or HTML plus title, optional metadata, word count, source URL, and fetch timestamp. Sample rowType is web_content. Article Content Extractor is for article-shaped news, blog, newsroom, and press URLs (maximum 300) when you need headline, byline, publish date, article body, excerpt, and hero image. Meta Tag & OpenGraph Scraper is a technical SEO head-metadata audit (title, canonical, robots, Open Graph, Twitter Card, hreflang, JSON-LD, issue flags) and does not emit cleaned page body. Use this Actor for site-page body cleanup. Use Article Content Extractor for article body. Use Meta Tag & OpenGraph Scraper for crawler and social head tags.

How does Website Content Extractor deliver dataset, webhook, and dry-run output?

delivery defaults to dataset. A non-dry-run always writes canonical dataset rows first; webhook delivery runs only after dataset and pay-per-event output succeed. webhookUrl is used when delivery is webhook and is skipped on dryRun. dryRun validates the setup and writes only local output: dataset writes and webhook delivery are disabled.

Does Website Content Extractor emit a Site QA or RAG report?

No. This Actor returns bounded source rows. The README positions it as the low-cost extraction step, then you pass the same URLs to a linked Site QA or RAG report Actor in a separate run. Do not treat raw markdown as the buyer-facing deliverable. Linked report actors have separate report and export events; do not infer those charges from a raw content row.

What happens to failed, no-content, dry-run, and unchanged Website Content Extractor rows?

Failed or no-content rows should stay out of the default dataset. Dry runs, validation-only runs, missing-key warnings, and unchanged recurring polls should not write payable default-dataset rows. Result events are charged per default-dataset item ($0.009 each; $9.00 per 1,000). Actor Start is a separate $0.001 event charged when the Actor starts (one event per GB, minimum one event).

Do generateReport and emitExport belong on this extractor input?

No. The README says do not add report-only fields to this extractor input. generateReport, emitExport, authorizedUseConfirmed, and emitUnchanged are shown as a separate input for a linked Site QA or RAG report Actor, not for Website Content Extractor. additionalProperties is false on this Actor, so unpublished report aliases are not accepted.

What is the URL cap, and which unpublished fields are rejected?

Maximum 200 URLs per run. Required field is urls. Live schema names are urls, outputFormat, includeMetadata, concurrency, timeoutMs, delivery, webhookUrl, dryRun, and maxChargeUsd. additionalProperties is false. Unpublished report-only names such as generateReport, emitExport, authorizedUseConfirmed, and emitUnchanged are not working inputs on this extractor.

How does maxChargeUsd cap billable Website Content Extractor rows?

maxChargeUsd defaults to 1 as a safety cap for this run. Billable rows beyond that cap are returned as no-charge limit_reached summaries. It does not replace the live PPE events: Actor Start at $0.001 and result at $0.009 per default-dataset item.

Should news, blog, newsroom, or press URLs go to Website Content Extractor?

No. Route article-shaped news, blog, newsroom, and press URLs to Article Content Extractor when you need headline, byline, publish date, article body, excerpt, and hero image (maximum 300 URLs; markdown or text, no HTML emit). This Actor is for broader site pages that are not article-shaped (maximum 200 URLs; markdown, text, or HTML).

Does Website Content Extractor audit Open Graph, robots meta, or JSON-LD issues?

No. This Actor cleans page body into markdown, text, or HTML. It does not produce a metadata-and-issue audit row. Title, canonical, robots, Open Graph, Twitter Card, hreflang, schema.org JSON-LD, and issue flags belong on Meta Tag & OpenGraph Scraper. There is no published full-page markdown field on that metadata Actor, and no published Open Graph issue list on this one.
