How is GDPR & CCPA Cookie Compliance Scraper different from DMARC & Email Security Checker and Trust Center Subprocessor Monitor?

GDPR & CCPA Cookie Compliance Scraper (taroyamada/privacy-cookie-compliance-scanner): This Actor fetches public homepages (and optional privacy/cookie policy URLs) to look for cookie-banner and policy signals for compliance-audit evidence. Each sites[] item requires homepageUrl; policy URLs auto-discover if omitted. Maximum 100 sites per run. Not a penetration test, consent-management platform, or legal opinion. Passive public-page scanning only. Not itself a SOC2 certification. DMARC & Email Security Checker is for Email DNS posture (input domains; DNS TXT; DMARC/SPF/DKIM rows). Not cookie banners. Trust Center Subprocessor Monitor is for Trust-center vendor lists (input trust-center URLs; public subprocessors pages; vendor-list diffs). Not cookie-banner scans. Website Content Extractor is for Policy page markdown (input urls; HTML body; markdown). Not banner/compliance scoring.

What input is required?

Live required fields: sites. exampleRunInput scans vercel.com with privacyPolicyUrl, region EU, concurrency 1. Schema prefill matches Vercel. Max 100 sites. Only scan properties you are authorized to check.

Field Type Default Notes
sites array required empty Sites to scan. List of sites to scan. Each entry requires a homepageUrl; privacyPolicyUrl and cookiePolicyUrl are auto-discovered if omitted. Quickstart: begin with one site. Maximum 100 per run.
delivery string dataset Delivery mode. Starter path: dataset keeps the first run low-friction. Advanced path: webhook sends the same payload to your endpoint for compliance ops or agency handoff.
webhookUrl string empty Webhook URL. Advanced delivery only: required when delivery is webhook. Must be a valid http(s) URL.
snapshotKey string privacy-cookie-compliance-snapshots Snapshot key for recurring checks. Keep this stable when moving from the quickstart to recurring compliance monitoring so policy drift stays comparable run to run.
concurrency integer 2 Concurrency. Parallel site checks. Keep at 1-2 for quickstart runs; increase for larger compliance portfolios.
batchDelayMs integer 500 Batch delay (ms). Pause between batches to keep scans polite and avoid rate limiting.
requestTimeoutSecs integer 20 Request timeout (seconds). Per-request timeout for fetching homepage, privacy policy, and cookie policy pages.
followRedirects boolean true Follow redirects. Follow HTTP redirects before scanning pages so canonical URLs are evaluated correctly.
dryRun boolean false Dry run. Preview scan results without saving snapshots, dataset rows, or sending webhooks.

How do dataset, webhook, and dry-run delivery work?

delivery defaults to dataset on the live schema. Dataset output is the billable surface when rows are written. webhookUrl is used when delivery is webhook (and typically not during dryRun). dryRun true validates or samples without the usual dataset/webhook side effects described on the Store schema.
