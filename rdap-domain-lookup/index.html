RDAP Domain Lookup — registrar, dates, nameservers, and DNSSEC for many domains

RDAP Domain Lookup looks up registration data for many domains in one run through RDAP, the ICANN-standard successor to port-43 WHOIS, and returns registrar, dates, status codes, nameservers, and DNSSEC for each domain. Store id taroyamada/rdap-domain-lookup. Registrant, admin, and tech contact entities are ignored.

Current RDAP records, not DNS propagation or a change monitor

Use this page for a bulk lookup of the current registration record. The Actor reads the official IANA RDAP bootstrap file (data.iana.org/rdap/dns.json) to find the registry server for each TLD, then queries that server. Use RDAP Domain Expiry & Whois Scraper when you need expiry warnings and registration changes between runs. Use DNS Propagation Checker for public DNS across resolvers. No personal data is collected. Only registrar-level and domain-level fields are written. This Actor is not affiliated with ICANN, IANA, or any registry.

Use cases

  • Expiry monitoring for a domain portfolio, from the dates the registry publishes.
  • Checking registrar and name-server setup across client domains.
  • Enriching a lead or vendor list with domain age from the registration date.

How to start a run

  1. Open the Actor and start with the prefilled sample domains to see the output shape.
  2. Replace the list with your own domains. URLs are accepted. www. is stripped. The schema uses the hostname’s registrable part as typed.
  3. Export the dataset as JSON, CSV, or Excel, or call the Actor through the API.

Output fields

One dataset row per domain that the registry answers. Registrant, admin, and tech contact entities are not included.

Field Meaning
registrar, registrarIanaId Sponsoring registrar name and IANA ID
createdAt, updatedAt, expiresAt Registration, last-changed, and expiration dates, as published by the registry
domainStatus EPP status codes (for example client transfer prohibited)
nameservers Delegated name servers
dnssecSigned Whether the delegation is DNSSEC-signed
rdapServer The registry RDAP server that answered

Limitations

  • Some ccTLDs do not publish an RDAP server in the IANA bootstrap. Those domains are reported as no_rdap_server.
  • Field coverage depends on each registry. Thin registries (for example .com) return registrar-level data only.
  • Lookups are rate-limited: low default concurrency, a delay between batches, and retry with backoff on HTTP 429, to respect registry limits.
  • Domains that fail (invalid, not registered, TLD without RDAP, or a registry error) are not written to the dataset. They are saved to the key-value store record FAILED_DOMAINS with the reason.
  • Data comes from public RDAP services operated by domain registries, located via the IANA bootstrap registry. Use the output in line with each registry’s RDAP terms of use.
