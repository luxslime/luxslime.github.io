Low-cost raw review check

The default path keeps raw review behavior and a small page cap. mode defaults to snapshot. generateReport stays false so canonical rows are the raw review array.

{
  "podcastIds": ["1535809341"],
  "countries": ["us"],
  "maxPagesPerPair": 1,
  "generateReport": false,
  "maxChargeUsd": 0.5,
  "delivery": "dataset",
  "dryRun": false
}

Published raw fields: podcastId, country, page, reviewerName, rating, title, content, version, voteCount, updated, and reviewId, plus actorName, rowType, sourceUrl, fetchedAt, and billingEventName. README sample (placeholder review data):

{

  "rowType": "podcast_review",
  "billingEventName": "apify-default-dataset-item",
  "podcastId": "1535809341",
  "country": "us",
  "page": 1,
  "reviewerName": "public-reviewer",
  "rating": 1,
  "title": "A critical review",
  "content": "Public review text.",
  "version": "1.0",
  "voteCount": 0,
  "updated": "2026-07-31T00:00:00Z",
  "reviewId": "review-1",
  "sourceUrl": "https://itunes.apple.com/us/rss/customerreviews/id=1535809341/sortby=mostrecent/json",
  "fetchedAt": "2026-08-01T00:00:00.000Z"

sourceUrl is the official iTunes Customer Reviews RSS URL used for the row. Up to 25 unique podcast IDs, 10 unique country codes, and 10 pages per pair are accepted. Over-limit input fails instead of being silently truncated. A failed pair is reported in meta.warnings; successful pairs remain available.

High-value review report

Set generateReport to true when you need one aggregate podcast_review_report row. Raw reviews remain in the runtime reviews array and are not sent to the dataset. reportMode is summary.

{
  "podcastIds": ["1535809341", "1641234567"],
  "countries": ["us", "gb"],
  "maxPagesPerPair": 1,
  "generateReport": true,
  "reportMode": "summary",
  "maxChargeUsd": 2,
  "dryRun": false
}

The single report row includes showCountrySummaries (review count, average rating, five-point rating distribution, and latest review date for every show/country pair), totalReviewCount, lowRatingSourceLinkedSamples (up to ten rating-1 or rating-2 samples with source URLs), sourceUrls, generatedAt, fetchedAt, and billingEventName podcast-review-report. Scheduled delta monitor

Use a stable monitorKey on every scheduled run. The first baseline_only run stores the current feed with zero dataset rows and zero charge. Later runs emit only new or changed reviews; an unchanged poll remains zero rows and zero charge when emitUnchanged is false.

{
  "mode": "monitor",
  "monitorKey": "network-show-1535809341-us",
  "initialRunMode": "baseline_only",
  "emitUnchanged": false,
  "podcastIds": ["1535809341"],
  "countries": ["us"],
  "maxPagesPerPair": 1,
  "generateReport": true,
  "maxChargeUsd": 2,
  "dryRun": false
}

In mode=monitor, the runtime reviews array still holds the current fetched snapshot for diagnostics, while canonical rows contain only the new or changed delivery. State advances only after canonical pay-per-event delivery succeeds; partial source failures do not advance it. emit_backfill delivers the first snapshot instead of storing it with zero rows.

How is Apple Podcasts Reviews Scraper different from the search actor and the chart actor?

Reviews Scraper reads public Apple/iTunes Customer Reviews RSS JSON for collection IDs you already have. Canonical delivery is podcast_review rows, or exactly one podcast_review_report when generateReport is true. mode=monitor can emit only new or changed reviews after a baseline. It does not search by keyword, attach episode catalogs, snapshot Top Podcasts ranks, or emit rank-movement reports. Apple Podcasts Scraper is search, chartRequests snapshots, lookupIds, and optional recent episodes. Apple Podcasts Chart Scraper is storefront Top Podcasts ranks and optional movement reports.

What input is required for an Apple Podcasts review run?

podcastIds is required. The schema sets additionalProperties to false. Live input schema fields:

Field Type Default Notes
podcastIds string[] required iTunes collection IDs (numeric strings). At most 25 unique. Schema prefill is ["1535809341"].
countries string[] prefill ["us"] ISO-3166-1 alpha-2, lowercase. At most 10 unique.
maxPagesPerPair integer 1 Review pages per show/country pair (50 reviews each). Max 10 (iTunes cap).

generateReport boolean false When true, dataset gets exactly one podcast_review_report; raw reviews stay in runtime output.
reportMode string summary Published enum is summary only.

delivery string dataset Enum: dataset or webhook.
webhookUrl string — Required when delivery is webhook.

What fields are on a podcast_review dataset row?

Each delivered raw row has rowType podcast_review and billingEventName apify-default-dataset-item. Published fields are podcastId, country, page, reviewerName, rating, title, content, version, voteCount, updated, and reviewId, plus actorName apple-podcast-reviews-monitor, sourceUrl (the official iTunes Customer Reviews RSS URL used for the row), and fetchedAt. Review text is public source material for reputation and market research. The Actor does not infer private reviewer identity or claim Apple endorsement. Do not join these rows to Apple Podcasts Scraper or Chart Scraper schemas as one field list; see Apple Podcasts dataset fields.

When does generateReport replace raw rows with a podcast_review_report?

Set generateReport to true. Canonical dataset delivery then contains exactly one podcast_review_report row billed as the podcast-review-report event. Raw reviews stay in the runtime reviews array and are not sent to the default dataset. The report includes reportMode summary, showCountrySummaries (review count, average rating, five-point ratingDistribution, latestReviewDate per show/country pair), totalReviewCount, lowRatingThreshold 2, up to ten rating-1 or rating-2 lowRatingSourceLinkedSamples with source URLs, sourceUrls, generatedAt, fetchedAt, actorName, rowType, and billingEventName. reportMode has no other published enum value.

How does mode=monitor emit only new or changed reviews?

Set mode to monitor and pass a stable monitorKey on every scheduled run. Default initialRunMode baseline_only stores the first snapshot with zero dataset rows and zero charge. Later runs emit only new or changed reviews. Leave emitUnchanged false so an unchanged poll stays zero rows and zero charge. In monitor mode the runtime reviews array still holds the current fetched snapshot for diagnostics, while canonical rows contain only the new or changed delivery. State advances only after canonical pay-per-event delivery succeeds; partial source failures do not advance it. emit_backfill delivers the first snapshot instead of storing it with zero rows.

What are the podcastIds, countries, and maxPagesPerPair limits?

The Actor accepts at most 25 unique iTunes collection IDs, 10 unique ISO-3166-1 alpha-2 country codes (lowercase), and 10 review pages per show/country pair (50 reviews each; iTunes cap). Over-limit input fails instead of being silently truncated. Each source request has a timeout and bounded retry for network and server errors. A failed pair is reported in meta.warnings; successful pairs remain available. This is not Chart Scraper’s 20-country Top Podcasts cap and not Apple Podcasts Scraper’s single default country on search/lookup. Storefronts differ: see charts and search by country.

How does Reviews Scraper webhook delivery differ from dataset delivery?

delivery defaults to dataset and sends non-empty canonical rows through Actor.pushData. webhook sends the complete runtime envelope (meta, reviews, optional report, canonical rows, delivery, deliveryAudit) to webhookUrl and still sends only the canonical rows to the default dataset. Empty output does not issue a dataset POST. A non-2xx dataset response or dataset network failure fails the run; partial success is not reported as success. dryRun performs no external write. The published enum is dataset or webhook. After the payload shape is useful, see webhooks for delivery patterns used on the related Apple Podcasts actors — do not copy Chart Scraper’s webhook-first fail-closed rule onto this Actor.

The Actor uses public Apple/iTunes Customer Reviews RSS JSON only. No login, cookie, API key, CAPTCHA bypass, or private endpoint is used.

Does Reviews Scraper accept Apple show URLs, search terms, or episode feeds?

No. Required input is podcastIds (numeric iTunes collection ID strings). additionalProperties is false, so unpublished fields such as showUrls, searchTerm, lookupIds, chartRequests, includeEpisodes, or a public RSS feed URL are not accepted. Take a collection ID from an Apple Podcasts URL (id1535809341 becomes 1535809341) or get IDs first with Apple Podcasts Scraper search or lookupIds. This Actor does not search by keyword, attach episode catalogs, or parse publisher episode feeds. See search discovery and episode metadata export on the search actor.

Can this Actor scrape Shopify App Store or G2/Capterra reviews?

No. This Actor reads Apple/iTunes Customer Reviews RSS JSON for podcast collection IDs and storefronts only. It does not accept appUrls, Shopify slugs, or G2/Capterra reviewPageUrls. Shopify App Store Review Scraper reads apps.shopify.com listings. G2 & Capterra Review Scraper reads public G2 and Capterra product review pages. Use the Review Intelligence pack to choose among those three sources.

Does a failed show/country pair fail the whole Reviews Scraper run?

No. A failed pair is reported in meta.warnings; successful pairs remain available. Each source request has a timeout and bounded retry for network and server errors. Empty output does not issue a dataset POST. A non-2xx dataset response or dataset network failure fails the Actor run; that is a delivery failure, not a partial source warning. In monitor mode, partial source failures do not advance stored state.

How does maxChargeUsd fail closed before pay-per-event delivery?

maxChargeUsd defaults to 2. The Actor fails closed before PPE delivery if the estimated price of the rows actually delivered would exceed the cap. For report runs it checks fetched raw rows plus the report price contract before write; maxChargeUsd is then applied to the rows actually delivered (the single report row in report mode). Raw mode estimates against delivered apify-default-dataset-item rows. Report delivery uses Actor.pushData with the podcast-review-report event and requires chargedCount of at least 1 or the Actor fails closed.

What happens on a baseline_only first monitor run or an unchanged poll?

The default initialRunMode baseline_only stores the first snapshot with zero dataset rows and zero charge. Later unchanged polls with emitUnchanged false also emit zero rows and zero charge. Setting emitUnchanged true delivers unchanged reviews and bills them as apify-default-dataset-item events. emit_backfill delivers the first snapshot instead of a zero-row baseline. dryRun performs no external write on any of these paths.
