What it does

For each review-page URL you provide, the Actor:

  1. Classifies the URL as G2 (g2.com/products/*/reviews) or Capterra (capterra.com/p/*/reviews/) and routes it to the matching parser.
  2. Tries JSON-LD structured data first, then embedded app data (for example __NEXT_DATA__ on Capterra), then og:title meta for product-name fallback, then HTML pattern matching for reviews.
  3. Extracts product metadata — productName, vendorName, categoryName when available.
  4. Parses overall rating, total review count, and rating breakdown.
  5. Collects normalized review rows — title, rating, date, author, body, pros, cons, verified.
  6. Returns status and explicit warnings when a page is partial, blocked, or structurally changed, instead of failing silently.

How does JSON-LD, embedded app data, og:title, and HTML pattern matching recover G2 and Capterra reviews?

The published Parsing Strategy tries JSON-LD structured data first, then embedded app data (for example __NEXT_DATA__ on Capterra), then og:title meta for product-name fallback, then HTML pattern matching for reviews. The README presents that layered approach as graceful degradation when markup changes. Reviews are still extracted from server-rendered HTML; pages that render reviews only via client-side JavaScript may return partial results.

What happens if a G2 or Capterra page is blocked or the HTML changes?

The Actor emits explicit warnings when page shapes change or access is blocked, rather than silently returning bad data. It degrades gracefully and can return partial results (metadata without reviews) with status ok, partial, blocked, or error. Reviews are extracted from server-rendered HTML; pages that render reviews only via client-side JavaScript may return partial results. G2 and Capterra protect against automated access — blocked requests are reported honestly. HTML parsing is fragile; the Actor emits warnings when expected patterns are missing.

What does meta.implementationStatus report on a G2 or Capterra run?
