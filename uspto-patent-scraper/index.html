How is USPTO Patent Search Scraper different from PubMed Literature Watch and NIH Research Funding Landscape Report?

USPTO Patent Search Scraper (taroyamada/uspto-patent-scraper): This Actor searches public USPTO / PatentsView surfaces for patents matching a query (optional assignee and grant-date window) and returns structured rows with identifiers and source URLs. Optional apiKey uses PatentsView first; otherwise the Actor still runs on public sources. Not legal advice, prior-art clearance, or a full-text claims analytics suite. demoMode masks fields and caps output at 3. PubMed Literature Watch is for Scientific papers (input PubMed queries; NCBI; citation rows). Not USPTO patents. NIH Research Funding Landscape Report is for NIH awards (input org/term filters; NIH Reporter; award rows). Not patent grants.

What input is required?

Live required fields: query. exampleRunInput is query=artificial intelligence, maxResults 10, dryRun false, demoMode false. Optional PatentsView apiKey from patentsview.org/apis/keyrequest.

Field Type Default Notes
apiKey string empty PatentsView API Key (Optional). Optional. If set, PatentsView API is used first. Get one at: https://patentsview.org/apis/keyrequest
query string required empty Search Query. Patent search query (title, abstract, claims). Example: 'artificial intelligence machine learning'
assignee string empty Assignee Filter. Filter by assignee/company name. Example: 'Google'
dateFrom string empty Date From. Start date (YYYY-MM-DD). Patents granted on or after this date.
dateTo string empty Date To. End date (YYYY-MM-DD). Patents granted on or before this date.
maxResults integer 10 Max Results. Maximum number of results to return.
delivery string dataset Delivery Mode. How to deliver results. 'dataset' saves to Apify Dataset, 'webhook' sends to a URL. In demoMode, delivery is always dataset.
webhookUrl string empty Webhook URL. Webhook URL to send results to (only used when delivery is 'webhook'). Works with Slack, Discord, or any HTTP endpoint.
dryRun boolean false Dry Run. If true, runs without saving results or sending webhooks. Useful for testing.
demoMode boolean false Demo Mode. If true, limits output to 3 results, masks detailed fields, and disables webhook delivery.

Published Store example run input (omitted fields take schema defaults):

{
  "query": "artificial intelligence",
  "maxResults": 10,
  "delivery": "dataset",
  "dryRun": false,
  "demoMode": false

How do dataset, webhook, and dry-run delivery work?

delivery defaults to dataset on the live schema. Dataset output is the billable surface when rows are written. webhookUrl is used when delivery is webhook (and typically not during dryRun). dryRun true validates or samples without the usual dataset/webhook side effects described on the Store schema.
