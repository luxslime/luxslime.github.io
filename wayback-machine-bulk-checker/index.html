Look up Internet Archive snapshot availability and closest cache URLs for up to 500 known URLs

Wayback Machine Bulk Checker queries the Internet Archive Wayback Machine available endpoint for URL lists you already have (maximum 500 per run). It reports whether a URL was archived and, when present, the closest snapshot URL and timestamp. It is a read-only archive lookup — not live HTTP status QA, not nested sitemap XML discovery, and not a tool that saves new snapshots.

How is Wayback Machine Bulk Checker different from Bulk URL Status Checker and Sitemap Scraper & Analyzer?

This Actor queries the Internet Archive Wayback Machine available endpoint for a list of URLs you already have (urls, maximum 500). It reports whether a URL was archived and, when present, the snapshot closest to a target date. Bulk URL Status Checker checks a known URL list (urls, maximum 1000) for live HTTP status, redirect chains, response timing, and broken-URL findings; it does not query the archive. Sitemap Scraper & Analyzer reads sitemap.xml and nested sitemap indexes (sitemapUrls) to discover URL inventories, with optional HEAD checks for HTTP 200; it does not look up historical cache availability. Use this Actor for read-only archive availability. Use Bulk URL Status Checker for live HTTP QA. Use Sitemap Scraper & Analyzer to discover URLs from nested XML sitemaps.

What input is required for Wayback Machine Bulk Checker?

urls is required: URLs to check in the Wayback Machine (maximum 500). Schema editor is stringList. Schema prefill is https://example.com and https://google.com. Optional live schema fields are closest (YYYYMMDD; leave empty for the latest snapshot), concurrency (integer, default 3, minimum 1, maximum 5), maxChargeUsd (number, default 1, minimum 0, maximum 100), delivery (dataset or webhook, default dataset), webhookUrl (when delivery is webhook), and dryRun (boolean, default false). additionalProperties is false. The live schema description for urls is: URLs to check in the Wayback Machine (max 500). The live schema description for closest is: Find snapshot closest to this date (YYYYMMDD format). Leave empty for latest.

Which README Wayback input examples are not live schema fields?

The README Input table lists closest as YYYY-MM-DD and includes checkAvailability (boolean, default true). README examples labeled Bulk archived snapshot history and Domain change-detection digest send includeCdx, maxSnapshotsPerUrl, and compareToLatestLive. Those names are not in the live input schema. additionalProperties is false, so do not send them. Use closest in YYYYMMDD form (for example 20200101), not YYYY-MM-DD. Schema-valid published inputs use urls plus optional closest, concurrency, maxChargeUsd, delivery, webhookUrl, and dryRun. The README single-URL availability example (urls only) matches the schema.

What does a Wayback lookup result row contain?

The published README output table lists url, archived, closestSnapshotUrl, closestSnapshotDate (YYYYMMDDhhmmss), totalSnapshots, firstSnapshotDate, and lastSnapshotDate. The published README output example uses url, available, closestSnapshot (archive url and timestamp), and archivedVersions. README prose also describes the timestamp of the most recent snapshot, the direct Wayback Machine URL for cached HTML, and the HTTP status of the original capture. There is no published output_schema.json on the Store page. The sample is an illustration, not a live coverage guarantee. Treat snapshot counts, first/last capture dates, and original HTTP status as README-claimed columns, not as a published dataset schema.

delivery defaults to dataset. Does this Actor return cached HTML or a CDX full-history dump?

No. This Actor queries the Wayback Machine available endpoint. It returns structured lookup rows for availability and the closest snapshot metadata when present. It does not fetch live page HTML, does not extract article bodies, and does not dump CDX full history. The published schema does not include includeCdx, maxSnapshotsPerUrl, or compareToLatestLive. Website Content Extractor cleans live docs, pricing, policy, and product pages. Article Content Extractor cleans live news, blog, and press pages. Use this Actor when the job is historical cache availability, not live page text and not a CDX timeline.

How far back can I check?

Internet Archive has snapshots back to 1996. Coverage depends on whether a URL was crawled. Snapshots exist only where the Archive crawled the page; availability is not guaranteed per URL.

Why is a URL not available?

Either it was never archived, or Internet Archive excluded it (due to robots.txt or a removal request). The README also notes that archived can be false when the URL was not crawled yet, or robots.txt blocked it at the time.

Can I archive new URLs or trigger a snapshot?

No. This Actor only reads the archive. To save new pages, the README points to archive.org’s /save/ endpoint. To trigger a new snapshot, use the Wayback Machine Save Page Now feature manually. This Actor cannot create snapshots.

Is an Internet Archive API key required?

No. The published README positions the Actor as using the official Internet Archive available endpoint (archive.org/wayback/available) with no API key needed. The README compares a single lookup to curl against archive.org, with bulk processing, error handling, and structured dataset output as the difference.

Limits to keep in mind

  • Read-only: this Actor does not save new pages and cannot trigger a snapshot.
  • At most 500 URLs per run. Keep concurrency low (schema maximum 5) because Internet Archive rate-limits aggressive callers.
  • closest is YYYYMMDD. Leave it empty for the latest snapshot. Do not send README aliases such as checkAvailability, includeCdx, maxSnapshotsPerUrl, compareToLatestLive, or closestDate.
  • Coverage is not guaranteed per URL. Snapshots exist back to 1996 only where the Archive crawled the page.
  • A URL may be unavailable because it was never archived, blocked by robots.txt, or removed by a removal request.
  • Not live HTTP status QA, not sitemap XML discovery, not live HTML extraction, and not a CDX full-history dump.
