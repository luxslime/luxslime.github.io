How is TED, SAM.gov & Grants Bid Alerts different from Google News Scraper and PubMed Literature Watch?

This Actor is a public-sector procurement queue. It searches official TED, SAM.gov, and Simpler.Grants.gov notice APIs and returns normalized tenders, grants, deadline/status alerts, and optional award-watch or rebid signals. Google News Scraper is query-based Google News RSS discovery of headlines and article URLs; it does not read procurement notice APIs and it does not clean HTML. PubMed Literature Watch & Research Report queries NCBI E-utilities for citation metadata, literature-update reports, and new-PMID alerts; it is not a bid queue. This page is TED/SAM.gov/grants bid alerts, not news RSS and not PubMed.

What bid-alert payload surfaces does a procurement run emit?

A normal run returns four surfaces:

  1. meta.executiveSummary — current queue size, top buyers, review urgency, source mix, and whether the run is stable, watch, or action_needed.
  2. notices[] — one normalized tender or grant row per opportunity, with source, noticeId, title, buyer, deadlineAt, estimatedValue, signalTags, lanePriority, and a source-derived recommendedAction.
  3. alerts[] — recurring delta events such as deadline_changed, status_changed, or closing_soon, plus award-watch or rebid events when enabled. Empty starter runs still return alerts: [].
  4. warnings[] / errors[] — missing API keys, skipped sources, throttling, or degraded upstream responses.

Dataset delivery attaches the opportunity_record event name to each notices[] row. procurement_summary and alert_event are additive compatibility labels under meta and alerts[]. The actor continues to return top-level meta, errors, notices, and alerts; it does not emit top-level PPE-name aliases.

What happens when SAM.gov or grants lanes are skipped or throttled?

The actor does not pretend coverage is complete. It returns the useful sources it could fetch, then surfaces explicit warnings or source errors for the missing lane. If us is present without a SAM.gov key, the actor warns and skips that source instead of failing the whole run. SAM.gov and grants are additive, not required. Official endpoints used by the schema defaults are https://api.ted.europa.eu/v3/notices/search, https://api.sam.gov/opportunities/v2/search, and https://api.simpler.grants.gov/v1/opportunities/search.

When should award-watch or rebid-watch be turned on?

After the starter or recurring TED queue already proves useful. Those workflows are best when you care about incumbent movement, renewals, or follow-on phrasing more than net-new open bids. includeAwarded defaults to false. Turn it on for award watch, incumbent movement, or rebid monitoring.

How are overlapping TED, SAM.gov, and grants notices deduplicated?

The actor normalizes notices and deduplicates them across comparable identifiers so recurring queues stay cleaner when similar records appear across sources. Bid-alert prioritization rolls deadline pressure, value, award/rebid phrasing, and watch-term hits into the review queue.

How do recurring bid-alert runs and grants state snapshots work?

The actor is designed for daily or weekly recurring runs. datasetMode all emits the current matched opportunity queue. changes_only emits only stateful alert rows and writes zero rows when nothing changed. Grants closing-soon and status-delta alerts persist snapshots in a named Apify key-value store (default procurement-intel-grants-state) so deadline and status alerts stay comparable. grantsOpportunityStatuses default is posted,forecasted. grantsAlertClosingSoonDays default is 7.

How do dataset, webhook, and dry-run delivery bill procurement rows?

delivery defaults to dataset and writes billed output. Webhook mode first writes and bills the same canonical dataset/value rows through Actor.pushData, verifies chargedCount, then forwards the run payload. Webhook delivery never replaces dataset billing and does not create a free webhook-only path. Downstream webhook failure is treated as a warning without rebilling on retry. dryRun skips dataset writes and webhook delivery side effects while validating inputs. Runtime is Node.js 20+.

Do generateReport and emitExport create live billed events today?

Use the report/export path only after the narrow TED queue is useful. generateReport and emitExport are live schema opt-ins for one source-linked executive procurement report and/or one source-linked JSON opportunity export when matched notices or alerts exist. The live Store PPE tab currently bills only the opportunity or alert row event (apify-default-dataset-item at $0.008). The published README also names other report and export event titles; check the live pricing tab before treating those names as current billed events.

Which official notice APIs does this Actor call?

Schema defaults are the TED notices search API at https://api.ted.europa.eu/v3/notices/search, the SAM.gov opportunities API at https://api.sam.gov/opportunities/v2/search, and the Simpler.Grants.gov opportunities search API at https://api.simpler.grants.gov/v1/opportunities/search. This Actor does not scrape a procurement HTML UI, does not query Google News RSS, and does not call NCBI E-utilities. It is not a page HTML extractor.

Do watch terms change upstream TED, SAM.gov, or grants queries?

No. watchTerms highlight buyers, incumbents, frameworks, or competitor names in summaries and notice signals without changing upstream source queries. Add them after the first useful run. keywords, cpvCodes, and naicsCodes are the filters sent to source APIs.

Are empty bid queues or unchanged changes_only polls billed?

No. An empty result emits zero rows and zero charges, including for report/export mode. datasetMode changes_only writes zero rows when nothing changed, so unchanged polls incur zero row charges. maxChargeUsd is checked before any dataset write; if the cap is too low, the actor fails closed instead of delivering a partial bundle. Zero means no cap.
