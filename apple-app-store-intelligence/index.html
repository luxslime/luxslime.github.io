How is Apple App Store Scraper different from Chrome Web Store Extension Intelligence and Website Content Extractor?

Apple App Store Scraper — Ratings, Reviews & Metadata (taroyamada/apple-app-store-intelligence): This Actor uses public iTunes lookup plus RSS customer-review feeds for App Store URLs or numeric IDs. reviewLimit defaults to 100 (max 500, RSS ~500 per storefront). maxChargeUsd default 1 fails closed with no-charge limit_reached summaries. Not Google Play, Chrome Web Store, or a private App Store Connect export. Public lookup/RSS only. Chrome Web Store Extension Intelligence is for Chrome extensions (input extensionUrls / searchTerms; Chrome Web Store HTML; extension metadata). Not Apple App Store. Website Content Extractor is for Generic page markdown (input urls; HTML body; markdown). Not iTunes lookup/RSS reviews.

What input is required?

Live required fields: appUrls. exampleRunInput is Spotify US URL, reviewLimit 50. Schema default reviewLimit 100 and maxChargeUsd 1. Prefer keeping first runs under the cap.

Field Type Default Notes
appUrls array required empty App URLs. One or more Apple App Store URLs (e.g. https://apps.apple.com/us/app/spotify/id324684580) or numeric app IDs (e.g. 324684580).
country string us Country / Storefront. Two-letter storefront code (e.g. us, gb, jp). Controls which country's reviews are fetched and which pricing/availability is returned.. minLength=2
reviewLimit integer 100 Review Limit. Maximum reviews to collect per app (1–500). Reviews come from Apple's public RSS feed, limited to ~500 per storefront.
timeoutMs integer 20000 Timeout (ms). HTTP request timeout per API call in milliseconds.
delivery string dataset Delivery. Where to send results: dataset or webhook.
webhookUrl string empty Webhook URL. Webhook URL to POST results to when delivery=webhook.
dryRun boolean false Dry Run. Run without saving results to dataset or webhook.
maxChargeUsd number 1 Maximum charge (USD). Safety cap for this run. Billable rows beyond this cap are returned as no-charge limit_reached summaries.

Published Store example run input (omitted fields take schema defaults):

How do dataset, webhook, and dry-run delivery work?

delivery defaults to dataset on the live schema. Dataset output is the billable surface when rows are written. webhookUrl is used when delivery is webhook (and typically not during dryRun). dryRun true validates or samples without the usual dataset/webhook side effects described on the Store schema.

What does a result contain?

README sample uses ellipses and is not valid JSON. Illustration keys: appId, url, country, retrievedAt, metadata (name, developer, bundleId, primaryGenre, icon, version, ageRating, languageCodes), rating, pricing, reviewSamples, rollups.themes. Treat README samples as illustrations, not a live coverage guarantee. There is no published output JSON schema on the Store page.
